### 2.2 必须保持的行为事实（重构不变量）

以下事实逐一核对过现有源码，重构不得改变。数字对照是必要验收条件，但不是过程不变量保持的充分证明；涉及仿真顺序、请求接受、LFSR、拒绝时机和提交采样的改动，还必须按 §5.2 逐条做静态核对，并用 check-waves 做独立波形对照。

- **F1 复位**：`sim_reset` 清零周期/退休计数与全部在途请求、LFSR 置 0xACE1；`reset=1`，`clock=0` eval → `clock=1` eval → `reset=0` 且输入清零 → 再 eval。复位期间不计周期。
- **F2 每拍顺序**：`clock=0` + `eval_step`（dump 波形、time+1）→ 采样 commit/pc/inst → 非法/未对齐检查 → 存储器请求簿记 → `clock=1` 直接 `dut.eval()`（不 dump、不 timeInc）→ `++cycles` →（若提交）`++retired` → 到期则写内存 → 驱动 `io_*_rdata/respValid` → `eval_step`（dump、time+1）→ 可选逐拍打印。**上升沿用裸 eval，不用 eval_step；时间每拍只推进两次。无新回复时 rdata 保持上一拍的值，只把 respValid 拉低，不得清零。**
- **F3 非法指令**：IDU 对 illegal 关闭 `mem_read/mem_write`，因此 `is_mem=0`、`normal_done=1`，**illegal 拍 `commit=1`**。测试台在上升沿**之前**拒绝：clock 停在 0，不计周期、不计退休，但 attempts 计入该拍。拒绝拍只发生一次低电平求值（仿真时间 +1），不产生上升沿与尾部求值；正常完成的拍推进两次仿真时间。当前 `sim_step` 打印后返回 false。
- **F4 ebreak**：`halt = halt_raw && commit`，DPI 在上升沿回调，retired 包含 ebreak；halt_pc 由 DPI 记录。
- **F5 计数口径**：`cycles` = 上升沿次数；`retired` = 成功提交的指令数（含 ebreak、不含被拒绝；AM 图里 instructions 即此值）；`attempts` = 上升沿前采样到 commit=1 的次数（含被拒绝与未对齐拍）。
- **F6 存储器延迟**：LFSR 16 位、初值 0xACE1、仅在**接受一笔新请求**时推进一次（固定延迟模式下不推进 LFSR）。"接受"的精确条件：该拍低电平求值后 `!pending && reqValid`；等待中的请求不推进 LFSR，回复当拍也不会接受新请求（pending 在稍后的回复逻辑中清零）。IFU 块先于 LSU 块；同一拍两者都接受时，LFSR 先为 IFU 推进、再为 LSU 推进。延迟 `1 + lfsr%20`；接受请求当拍即自减；`NPC_MEM_DELAY=1..20` 覆盖为固定值；等待期间第二个请求被静默忽略（本轮不改；步骤 6 才做协议监视）。
- **F7 设备与地址**：见 §2.1 pmem 行。UART 写落 stderr；计时读依赖 `sim_cycles()` 与 404 MHz。
- **F8 结束**：`gotFinish` 置位后不得开始新的拍、不得再产生上升沿；当前拍已开始的尾部 `eval_step` 仍要执行完。当前 `sim_step` 在入口处直接返回 true 不推进。
- **F9 预算现值**：main 5e11 周期；cpu_test 64000 周期；difftest 1e7 提交尝试、`64×1e7+3` 周期；SoC 1e8 周期（本轮不动）。Python 墙钟：run_cpu_tests 15 秒、run_acceptance 20 秒。
- **F10 DiffTest 顺序**：NPC 一拍、EMU 一条；参考模型只在提交/拒绝时推进；每步主计数固定 17 项（PC 或 `pc.before_ebreak` + x0..x15）；辅助检查含 pre_pc/inst/illegal/accepted/rs 读/halted/finish/halt_pc；**设备读同步**：`emu.step()` 之后、比较之前，若 `info.device_load` 且目标寄存器非 x0，先用 NPC 同号寄存器覆盖 EMU（`emu.set_reg`）；结束后全量比较 128 MiB（33554432 字），相同字只计数；`argc==2` 时是 AM 模式，额外要求 a0==0。
- **F11 EXPECT 语义**：`halt`(1)、`cycles`(1)、`instructions`(1，含 ebreak)、`cycles_random`(1，仅在延迟=随机时检查)、`cycles_fixed D N`(2，仅在生效延迟=D 时检查)、`reg`(2，编号 1..15)、`mem`(2，4 字节对齐、[0x80000000,0x88000000))、`illegal`(2，PC+编码)、`trace`(≥1)。检查项数量与顺序不得改变（每案例 `PASS: N checks` 必须与基线一致）。
- **F12 Python 现状**：run_cpu_tests 解析 `PASS:` 行生成摘要、单案例 15 秒；run_acceptance 解析 EMU 的 step/a0/ebreak 文本、无 try/except，超时会中断整批。
- **F13 Makefile 关系**：`Makefile.diff` include `Makefile.cpptest`；`Makefile.wave`、`Makefile.test` 同理；`Makefile.cpptest` include `tests/Makefile.mk`；AM 侧 `scripts/platform/npc.mk` 通过 `make -C npc -f Makefile.cpptest run` / `-f Makefile.diff diff` 调用，命令名不能变。
- **F14 波形**：`VM_TRACE_FST` 条件编译；`traceEverOn` 由入口决定；资源释放顺序按现源码：先 `dut.final()`，再 `wave_trace->close()` 与 `wave_trace.reset()`；波形对象必须在 dut 与 VerilatedContext 析构前销毁。不要按常见示例调整顺序。
- **F15 CLI**：`sim <bin> [wave.fst]`；`cpu_test <bin> <expect> <name> [wave.fst]`；`difftest <bin> [<expect> <name>]`；`soc <wave?>`。本轮不变。

## 3. 目标设计

### 3.1 三个概念

| 概念 | 归属 | 回答的问题 |
|---|---|---|
| 单拍事件 `step_event` | sim 核心 | 这一拍发生了什么 |
| 停止原因与运行结果 `stop_reason` / `run_result` | 运行循环 | 为什么停、停在哪、跑了多少 |
| 判定策略 | runner | 这次停止算不算通过 |

仿真层只报告事件，不打印错误、不判通过；runner 决定通过标准；Python 只看退出码与 RESULT 行。

### 3.2 词汇表

**step_event**

| 值 | 条件 | 时钟 | 计数 |
|---|---|---|---|
| `waiting` | 本拍未提交、无故障 | 推进 | cycles+1 |
| `committed` | 本拍提交一条非 ebreak 指令 | 推进 | cycles+1、retired+1 |
| `halted` | 本拍提交 ebreak，DPI 已通知结束 | 推进 | cycles+1、retired+1 |
| `rejected` | 上升沿前检测到非法指令 | **不推进** | attempts 已计，cycles/retired 不变 |
| `fault` | 上升沿前检测到取指未对齐 | **不推进** | cycles/retired 不变（attempts 可能已在采样时 +1） |

**stop_reason**

| 值 | 含义 | 是否通过 |
|---|---|---|
| `running` | 尚未停止 | — |
| `ebreak` | 正常结束 | 按各入口规则 |
| `rejected` | 停在非法指令 | 只有声明了 `illegal` 期望的案例；其他入口失败 |
| `fetch_unaligned` | 取指未对齐 | 一律失败 |
| `cycle_limit` | 周期预算耗尽 | 失败 |
| `attempt_limit` | 提交尝试预算耗尽 | 失败 |
| `external_finish` | gotFinish 但无 ebreak | 失败（异常） |
| `comparison_mismatch` | 仅 DiffTest：任一比较字段不一致 | 一律失败 |
| `reference_fault` | 参考模型执行异常（DiffTest 或独立 EMU） | 一律失败 |

**run_result 字段**：`reason`、`stop_pc`（停止拍上升沿前采样的 PC；ebreak 用 halt_pc）、`stop_inst`、`cycles`、`retired`、`attempts`、`mem_delay`（0=随机，1..20=固定）。

**RESULT 行**（每个进程恰好一行，程序自行打印；解析规则见 §6.3–§6.4）：

```
RESULT case=<无空格> backend=<am|npc|diff|emu> verdict=<pass|fail> stop=<stop_reason> pc=0x%08x inst=0x%08x cycles=%llu retired=%llu attempts=%llu checks=%u failures=%u delay=<random|fixed:N> [扩展字段]
```

- `backend=diff` 追加：`core=%llu core_fail=%u extra=%llu extra_fail=%u memory=%llu memory_fail=%u`；`checks/failures` 只计 EXPECT 检查。
- `backend=emu` 用另一行格式：`RESULT case=... backend=emu verdict=... stop=... retired=%llu a0=0x%08x halt_pc=0x%08x`（无 cycles/delay）。
- 初始化失败等未进入运行的情况**不打印** RESULT；脚本按"缺失即失败"处理。

### 3.3 sim 接口（建议头文件）

签名可按编译需要微调，但事件/原因取值、计数口径和 RESULT 字段名必须一致。

```cpp
#ifndef NPC_SIM_H
#define NPC_SIM_H
#include <cstdint>

class Vysyx_00000000;

enum class step_event { waiting, committed, rejected, halted, fault };
enum class stop_reason {
    running, ebreak, rejected, fetch_unaligned,
    cycle_limit, attempt_limit, external_finish,
    comparison_mismatch, reference_fault
};

struct run_limits {
    std::uint64_t max_cycles = 0;    // 0 表示不限
    std::uint64_t max_attempts = 0;  // 0 表示不限
};

struct run_result {
    stop_reason reason = stop_reason::running;
    std::uint32_t stop_pc = 0, stop_inst = 0;
    std::uint64_t cycles = 0, retired = 0, attempts = 0;
    unsigned mem_delay = 0;
};

class sim_session {
public:
    sim_session() = default;
    ~sim_session();                       // 关闭波形 + dut.final()
    sim_session(const sim_session&) = delete;
    sim_session& operator=(const sim_session&) = delete;

    bool init(Vysyx_00000000& dut, const char* wave_path); // 原 sim_init 全部职责
    void reset();                                          // 原 sim_reset 全部职责
    step_event step(Vysyx_00000000& dut);                   // 推进一拍，见 §3.2
    run_result result(stop_reason reason) const;             // 用当前计数填充

    bool halted() const;
    std::uint32_t halt_pc() const;
    std::uint64_t cycles() const;
    std::uint64_t retired() const;
    std::uint64_t attempts() const;
    unsigned mem_delay() const;

private:
    Vysyx_00000000* dut_ = nullptr;
    // 其余实现细节放 sim.cpp；进程内只有一份计数与在途请求状态
};

// 兼容既有调用（pmem、expectations、dpi 使用）
void sim_set_verbose(bool enabled);
unsigned sim_memory_delay();
std::uint64_t sim_cycles();
std::uint64_t sim_instructions();
bool sim_halted();
std::uint32_t sim_halt_pc();
```

### 5.2 `sim_session::step` 算法（必须逐条保持顺序）

1. 调用者必须在 `gotFinish` 后停止调用 `step`；若仍被调用，不推进、stderr 提示一次、返回 `waiting`（正常流程不得依赖该分支）。
2. `clock=0`；`eval_step`（dump、time+1）。
3. 采样 `commit/pc/inst`；若 `commit` 则 `++attempts`；保存 `last_pc/last_inst`。
4. `pc%4 != 0` → 返回 `fault`（clock 保持 0）。
5. `illegal` → 返回 `rejected`（clock 保持 0）。
6. IFU/LSU 请求簿记与延迟自减，生成回复与写使能（逐行保持现有实现）。
7. `clock=1`；裸 `dut.eval()`（不 dump、不 timeInc）；`++cycles`。
8. 若第 3 步采样到 `commit`：`++retired`。
9. 到期写内存 → 驱动 `io_ifu_rdata/io_ifu_respValid/io_lsu_rdata/io_lsu_respValid` → `eval_step`（dump、time+1）。
10. verbose 且 commit：打印 `pc/inst/next_pc`。
11. 若 `sim_halted()` → 返回 `halted`；否则 commit → `committed`；否则 `waiting`。DPI 在上升沿内置位 `gotFinish` 不改变本拍流程，第 9 步的尾部求值照常执行。

`result(reason)`：`stop_pc/stop_inst` 取本拍采样值；`reason==ebreak` 时用 `halt_pc`；预算耗尽时取当前最后求值后的 pc/inst（下一条未执行指令），不额外 eval；填充 `cycles/retired/attempts/mem_delay`。

### 5.3 各入口事件处理

- **am_main**：循环 `while (!ctx.gotFinish())`；顶部检查 `cycles >= 5e11` → 打印现有超时信息并跳出（保持旧行为：随后仍执行 checker 并返回失败）。`rejected`/`fault` → 打印原 stderr 诊断（文本保持 "illegal inst: pc=... inst=..." / "unaligned fetch: pc=..."）并返回 1。其余打印与检查不变。
- **cpu_test**：循环条件 `!ctx.gotFinish() && cycles < 64000`；采样 `commit||illegal` 时记录 trace；`rejected`/`fault` → `step_failed=true` 并跳出。`check_expectations` 旧签名：`step_failed`、`sim.cycles()`。
- **difftest**：预算检查顺序与旧代码一致：每轮先看 `attempts < max_attempts`（循环条件），再在循环顶部检查 `cycles >= max_cycles`；等于上限即停止。无 commit 的等待拍继续步进；提交拍按现顺序处理：**在调用 `step()` 之前**直接读 `cpu_view` 采样 `pre_pc/inst/rs1_data/rs2_data` 与 `commit`，只读信号、不调用 eval、不得把采样移到 `step()` 之后或增加额外求值；随后 `step` → `emu.step()` → 设备读同步 → 比较。`accepted = (event==committed || event==halted)`；`rejected = (event==rejected)`；`comparison_mismatch` 由差异产生，`reference_fault` 由 EMU 故障产生。两个分支的事件必须与预采样一致：提交分支只允许 `committed/halted/rejected`，等待分支只允许 `waiting`；出现不一致按内部错误立即失败并报告，不得当普通差异处理。未对齐故障直接失败并报告 `fetch_unaligned`（不再折算成 accepted 比较差异；退出码不变）。被拒绝指令：比较后 `step_failed=true` 跳出。

### 6.3 RESULT 输出

- `sim_print_result` 按 §3.2 实现；作为程序输出的最后一行，每个进程恰好一行。
- am_main：`backend=am`，`case=` 程序文件名（不含路径），`checks/failures` 取 checker。
- cpu_test：`backend=npc`，`case=argv[3]`，`checks/failures` 取 checker。
- difftest：`backend=diff`，`case=argv[3]`（无 EXPECT 时取程序文件名），`checks/failures` 取 EXPECT 的 checker；扩展字段填 core/extra/memory 计数。
- 失败路径（比较失败、预算耗尽、故障、EXPECT 不过）也要打印 RESULT，`verdict=fail`。
- 初始化失败（参数、装载、波形打开）不打印 RESULT。
- **diff 的 verdict 规则**：只有每一拍 core/extra 比较无差异、期望停止条件成立、128 MiB 内存无差异、可选 EXPECT 全过、AM 模式 a0==0 同时成立时才是 `verdict=pass`；任一组失败即 fail。无 EXPECT 时 `checks=0 failures=0` 不代表通过。
- **RESULT 唯一性**：每个进程最多打印一行 RESULT（失败路径算在内）；Python 若发现 0 行或多行，判该案例失败；`verdict=pass` 必须与退出码 0 一致，不一致判失败。

各停止原因的后续动作（必须与现有行为一致）：

| 停止原因 | am | npc（cpu_test） | diff |
|---|---|---|---|
| `ebreak` | checker 2 项（含 a0==0） | 跑 EXPECT | 末态检查 + 128 MiB + 可选 EXPECT / AM a0 |
| `rejected`（EXPECT 声明 illegal） | AM 模式不预期非法，按失败 | 由 EXPECT 判定 | 末态期望检查通过后，继续 128 MiB 与 EXPECT |
| `rejected`（非预期） | 立即失败，不跑 checker | 由 EXPECT 判定（通常失败） | 立即失败，不比较内存 |
| `fetch_unaligned` | 立即失败 | 跑 EXPECT（通常失败） | 立即失败，不推 EMU、不比较内存 |
| `comparison_mismatch` | — | — | 立即失败，不比较内存 |
| `reference_fault` | — | — | 立即失败，不比较内存 |
| `cycle_limit` / `attempt_limit` | 跑 checker（hit ebreak 失败） | 跑 EXPECT（通常失败） | 立即失败，不比较内存 |
| `external_finish` | checker 失败 | EXPECT 失败 | 末态检查失败，不比较内存 |

上表所有路径共同遵守：退出循环后不得再调用 `step`；失败路径必须打印唯一一行 `verdict=fail` 的 RESULT 并返回 1（初始化失败除外，无 RESULT）；由 EXPECT/checker 决定结果的路径按其 `report()` 返回 0/1；资源由 `sim_session` 析构释放。

## 11. 易错点清单

1. **非法指令 `commit=1`**：漏计 attempts 或误计 retired 会改变 DiffTest 的 `PASS: N (M steps x 17)` 与 trace 检查。
2. **拒绝拍不推进时钟**：`rejected`/`fault` 返回时 clock 必须停在 0；补一个上升沿就会改变周期与 PC。
3. **上升沿用裸 `dut.eval()`**：不能换成 `eval_step`，否则波形时间点与 VCD 检查（0x80000038/34/3c）会漂移。
4. **`gotFinish` 后不得开始新的 step**：DPI 在上升沿内置位后，当前拍仍要完成尾部 `eval_step`；下一轮循环不得再推进。
5. **LFSR 只在接受新请求时推进**：等待拍推进 LFSR、或复位时漏掉种子重置，都会改变 hello 的 546583。
6. **延迟自减包含接受请求当拍**：写成下一拍开始计数会把最小延迟从 1 变成 2。
7. **写内存在上升沿 eval 之后、回复 eval 之前**：顺序反了会让 load 读到旧值。
8. **`respValid` 只保持一拍**：每拍重设，不能累积；无新回复时 rdata 保持上一拍的值，不得清零。
9. **波形销毁顺序**：先 `dut.final()`，再关闭并销毁波形对象（`close` + `reset`），最后 dut 与 `VerilatedContext` 析构；与现 `sim_close` 一致，不要按常见示例调整。
10. **`VerilatedContext::commandArgs` 会处理 argv**：先解析自己的参数，再调用；不要把 `--case` 之类塞给它。
11. **移动源文件后清 build 目录**：Verilator 的依赖缓存按旧路径生成，不清会出现幽灵编译。
12. **`diff_collector::clear()` 清空 total**：每步新建收集器，累计放 runner。
13. **内存比较不构造字符串**：33554432 个字逐项构造 `memory[0x...]` 会拖慢数倍并可能耗尽内存；相同字只计数。
14. **EXPECT 检查数量**：`check_expectations` 的检查项数量与顺序不能变，否则每案例 `PASS: N checks` 与基线不一致。
15. **instructions 含 ebreak**；`reg` 编号只到 15（RV32E）；`mem` 地址必须 4 字节对齐且在 [0x80000000,0x88000000)。
16. **main 的 a0==0 只用于 AM 模式**；手写案例允许 a0 非零，不得套用。
17. **EMU 是独立参考模型**：只允许在 `main.cpp` 加 RESULT 行，不得改 `emu.cpp/emu.h`，不得用 NPC 结果替代 EMU 结果。
18. **SoC 只构建不运行**：构建失败不得靠放宽参数掩盖。
19. **RESULT 恰好一行**：每个进程只打印一行，以 `RESULT ` 开头；多行或缺失都判失败，`verdict` 必须与退出码一致。
20. **不删除被跟踪文件**：`npc/e4/`、`npc/tb/*.v`、`npc/tb/sim.cpp` 由用户在 Git 侧处理。
21. **改名只做机械替换**：§5.0 的改名不顺手改逻辑、不重排格式；改名后任何一个数字变化都说明不是纯改名，先回退排查。
22. **命名一律 snake_case**：新增或改名的类型、函数、变量、文件都用小写下划线，如 `step_event`、`sim_session`；禁止 `StepEvent` 这类驼峰。例外只有 §3.6 列出的 Verilator 生成名、参考模型名与格式关键字。
23. **提交前采样只读不 eval**：DiffTest 的 `pre_pc/inst/rs1_data/rs2_data` 在 `step()` 之前直接读 `cpu_view`，不得加 eval、不得移到 step 之后。
24. **设备读同步不能丢**：`emu.step()` 之后、比较之前，`device_load` 且目标非 x0 时先用 NPC 同号寄存器覆盖 EMU。
25. **比较失败不比较内存**：中途退出时 `memory` 计数为 0 表示"未执行"，不是"内存全过"。
