| `npc/build/verification/soc-difftest/` | 已保存 | 运行证据 |

### 对外接口

```bash
# 1) 从待测 Flash 内的 ELF 抽参考镜像，保留已注入的 mainargs
flash=../am-kernels/kernels/hello/build/hello-minirv-ysyxsoc.bin
tail -c +369153 "$flash" > build/hello-from-flash.elf
riscv64-linux-gnu-objcopy -O binary build/hello-from-flash.elf build/hello-ref.bin

# 2) 运行时开启比较
NPC_SOC_REF=build/hello-ref.bin make -f Makefile.soc run PROGRAM="$flash"
```

- 不设 `NPC_SOC_REF`：行为与现在完全一致，不做比较。
- 起点：第一条进入 `[0x80000000, 0x80800000)` 的提交；此时 `load_program` + 寄存器种子。
- 比较项：`pc`、`inst`、16 个 GPR，以及下一 PC 或停机 PC。拒绝路径不做逐条参考执行。
- `mcycle` / `minstret`：**v1 不比**，原因写进 README（CPU 走 `cpuClock`，参考模型按提交推进，口径不同）。
- 内存：**v1 不做全量比较**，PSRAM 模型无法像 `pmem_read` 那样直接读；靠逐条 GPR 覆盖。

### 提交沿与比较

1. 设备读同步，位置在 `emu.step()` 之后、比较之前：

```cpp
if (info.device_load && info.device_load_rd != 0)
    emu.set_reg(info.device_load_rd, rf[info.device_load_rd]);
```

2. 计数器读只同步本条指令的非 x0 目的寄存器。停机时先对齐停机状态，再比较 `halt_pc`。

3. 结束输出：

```
RESULT case=<镜像名> backend=socdiff verdict=pass|fail commits=<N> mismatches=<M> halt_pc=0x........ device_reads=<N> counter_reads=<N>
```

### 接口

共用沿前采样入口：

```cpp
void sample_cycle(const bus_cycle_sample& sample, std::uint64_t cycle);
```

SoC 用 `NPC_SOC_BUS=1` 启用。每个 `cpuClock` 上升沿前采样 core0 的取指、数据请求和回复，与 P1-6 共用提交、PC 和指令样本。监视先处理回复，再判断该指令是否可以提交。独立 NPC 与 CSR 自驱复用此入口。

输出：RESULT 追加 `bus=pass|fail`。

## 4. #9 完整 printf RTC 的逐间隔稳定性

| 文件 | 作用 |
|---|---|
| `npc/tests/soc-timing/calibrate_wallclock.py` | 采集与统计 |

| `npc/build/verification/rtc-interval-stability/` | 本轮证据 |

### 接口

- 环境变量 `NPC_RTC_RUNS` 选同系数、同镜像连续通过轮数，范围 2～5，默认 2。
- 轮次结果记录 `intervals_seconds`、`interval_observations` 和 `per_interval_stats`。通过后记录 `same_q_run_stats`，单间隔阈值为空。

- **通过条件不变**：10 个间隔均值在 1 秒 ±5%，且最大目标迟到 < 1 秒。
- 逐间隔统计只作**记录**，不作通过条件（主机调度不可控，单间隔 0.81～1.68 秒是已知现象）。
