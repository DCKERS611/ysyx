# 同步与推送指导

正式源码：WSL Ubuntu-22.04 的 /home/ysyx/ysyx-workbench。
Windows 副本：E:/ysyx/e/e7；Git 仓库：E:/ysyx。

## 路径与范围

所有同步文件保留工作台相对路径。例如 npc/tests/soc_main.cpp 对应 E:/ysyx/e/e7/npc/tests/soc_main.cpp；ecc/npc-e7/runs/<run-id> 仍放同名路径。不能改放 verification 替代原件。

同步当前 E7 RTL、C/C++、Makefile、脚本、测试源码、配置和说明文档；同步两份预编译 klib-minirv-npc.a、klib-minirv-ysyxsoc.a，它们是必要构建输入。同步冻结的验收镜像、结果 JSON、日志、精简 FST 和综合报告，以保留结论依据。历史失败证据保留原状态。

不同步普通编译对象、宿主可执行文件、obj_dir、缓存、锁文件、嵌套 .git、工具链与 PDK 安装目录；派生的大体积 VCD 可由保留的 FST 重新生成。测试目录内 build 默认排除，明确列入验收清单的 build 证据例外。

Windows 独有 README、学习记录、本地学习计划和资料不能被覆盖或删除。本地学习计划按既有约定不提交；它不是本次从 WSL 同步的文件。E5 等其他阶段不进入 E7 提交。

## 操作顺序

1. 核对学习记录、正式源码和本轮验收结果。
2. 列出本轮要发布的源码和已经结束的验收证据。全量审计使用 `tools/sync_wsl_snapshot.ps1`。分批同步可参照 `verification/2026-11-06/final-acceptance/sync_scoped.py` 的路径和排除规则，其中 `--completed-only` 对应当时固定的范围。
3. 为本轮另存清单，逐项记录原相对路径、字节数与 SHA256，核对源与副本一致。P1 及个人波形的发布清单在 [release-sync](verification/2026-11-08/release-sync/sync-manifest.json)。仍在运行的全量 train 保留在 WSL，等最终结果生成后再按原路径归档。
4. 本次同步清单中每个文件全部加入 Git，包括被通用 build 忽略规则覆盖的必要证据；只对清单路径使用 git add -f，禁止对整个仓库强制添加。
5. 暂存 E7 文档和测试索引，检查提交路径、大小和本地计划排除情况，提交后正常推送 origin/main。
6. 核对 git rev-parse HEAD 与 git ls-remote origin refs/heads/main 一致，再报告推送完成。

源码同步、测试通过、提交成功和远端推送成功分别记录。同步不等于重新运行测试。未来新增目录先更新同步范围，再执行上述流程。
