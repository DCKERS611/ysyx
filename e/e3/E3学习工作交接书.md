## 5. 接手后的工作顺序

1. 从上述 Windows 文档与 WSL 实际目录核对现状；先看 `git status`，保护框架仓库和 `lecture6` 现有改动，不清理用户文件。
2. 对照官方 32 题逐项建立“示例编译运行 / 源码理解 / 附加题 / 错误与修复”证据。优先从当前练习 32 的拆分函数接续，同时回填前面缺少证据的章节；不要因练习编号较靠后就跳过 0～31 的遗漏。
3. 先修复各项目自身的构建与测试问题，再分别使用其原有 Makefile 验证；不要临时发明与项目配置不一致的编译命令来宣称通过。
4. 最终核对 Missing Semester 六讲课后题和 C 的 32 题附加题，准备解释 Makefile、Valgrind、函数指针/OOP、作用域、文件 I/O、库和链表的实际代码。

教学方式：用户已有 E2 C 基础，针对当前代码和报错直接讲清楚；给短而可运行的例子，尊重现有代码风格与修改范围。用户只问“会怎样”时保持只读；明确要求修改时才改代码，不额外加入无关注释或文件。
