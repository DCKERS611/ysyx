E3 主要分为两部分：一是熟悉 Linux 开发环境和常用命令行工具，二是在 Linux 环境中继续学习 C 语言的工程化内容。相比 E2，这一阶段不再只关注语法本身，而是把编辑、编译、调试、测试、库和版本控制串成一套完整的开发流程。

我的练习代码和学习笔记统一放在 `E:\ysyx\e\e3`，其中：

- `missing-semester/` 保存 Linux 工具课程练习；
- `c_advanced/` 保存《笨办法学 C》的源码和工程练习；
- `c_advanced/lcthw/` 保存双向链表及链表算法库；
- `练习19-游戏崩溃与防护审计.md` 和 `C语言IO函数速记卡.md` 保存重点章节的整理笔记。

我使用 WSL2 中的 Ubuntu 22.04 作为开发环境，通过 `/mnt/e/ysyx` 访问当前仓库，并使用 GCC、Make、GDB、Vim、Git 和 Valgrind 完成练习。

## 二、Linux 基本使用

这一部分以 The Missing Semester 2020 的六讲为主。我没有只看视频，而是边看讲义边在终端中完成对应练习。

### 1. Shell 基础

我学习了 Linux 的目录结构、绝对路径和相对路径，以及 `pwd`、`ls`、`cd`、`mkdir`、`cp`、`mv`、`rm` 等基本命令。我还练习了文件权限、`chmod`、环境变量、命令查找和 `man` 帮助文档。

在输入输出方面，我掌握了标准输入、标准输出和标准错误，能够使用 `>`、`>>`、`2>`、`2>&1` 和管道组合命令，也能通过 `$?` 判断上一条命令是否执行成功。

### 2. Shell 工具和脚本

我学习了 Bash 变量、命令替换、引号、通配符、条件判断、循环和函数，并完成了 `marco`/`polo`、错误重试、文件内容检查等脚本练习。通过这些练习，我逐渐理解了脚本不是简单地把几条命令写在一起，还需要处理参数、退出状态和错误分支。

我还重点练习了 `find`、`xargs` 和文件名中包含空格时的安全处理方式，理解了 `find -exec` 与 `xargs` 在批量处理文件时的区别。

### 3. Vim

我完成了 `vimtutor`，并在后续 C 练习中持续使用 Vim。现在能够使用普通、插入、可视和命令行模式完成移动、删除、复制、粘贴、搜索替换以及分屏操作。我还根据自己的习惯整理了 `.vimrc`，并最终恢复了 Vim 默认的 `j` 向下、`k` 向上操作方式。

### 4. 数据整理

这一部分主要学习了如何使用命令行处理文本和日志。我练习了 `grep`、正则表达式、`sed`、`tr`、`sort`、`uniq`、`awk`、`head`、`tail` 和 `wc`，并把它们组合成管道完成单词统计、启动时间统计和多次开机日志差异分析。

刚开始看到复杂正则表达式和长管道时比较难理解，后来我学会了先确定输入格式，再把任务拆成过滤、提取、转换、排序和统计几个步骤，逐段检查每一级管道的输出。

### 5. 命令行环境

我学习了进程、PID、信号、前后台任务以及 `Ctrl-C`、`Ctrl-Z`、`jobs`、`bg`、`fg` 等操作，并编写了等待进程结束的脚本。

我还重点学习了 tmux 的会话、窗口和分屏，配置了鼠标、历史记录、窗口切换、分屏快捷键和状态栏颜色。这样即使终端关闭，我也可以保留正在运行的任务和工作现场。

### 6. Git 与配置文件

我理解了工作区、暂存区、本地仓库和远程仓库的关系，并练习了以下基本流程：

```text
git status → git diff → git add → git diff --staged
→ git commit → git push
```

此外，我还学习了分支、合并、冲突处理、`stash`、`restore`、`revert`、`reset`、`reflog` 和远程仓库。后来我把 Bash、Vim、tmux 和 Git 配置整理成 dotfiles，编写了符号链接安装脚本，在另一个 Ubuntu 环境中测试后发布到了 GitHub。

## 三、C 语言进阶

这部分主要参考《笨办法学 C》。我已经有 E2 的 C 语言基础，因此对变量、数组、循环和普通函数等内容进行了快速复习，把主要精力放在内存、函数指针、多文件工程、调试、库、测试和数据结构上。

### 1. 基础复习与内存

通过前面的示例，我重新练习了格式化输出、基本数据类型、数组、字符串、指针和结构体。练习 17 让我进一步理解了栈和堆的区别，以及 `malloc`、`calloc`、`realloc` 和 `free` 的使用。练习 18 则让我熟悉了函数指针、比较函数以及把函数作为参数传递的写法。

### 2. 简单对象系统

练习 19 使用结构体和函数指针模拟了对象、继承和多态。我理解到，这里的“多态”实际上是把操作函数的地址保存在对象原型中，再根据当前对象调用对应函数。

`Monster`、`Room` 和 `Map` 都把 `Object` 放在结构体开头，因此可以通过相同的起始地址把子对象看作父对象使用。`Object_new` 会复制原型并为缺失的操作填入默认实现。这不是 C 语言自带的面向对象，而是依靠结构体布局和函数指针人为建立的一套规则。

为了检查错误路径，我还编写了 `test_ex19.sh`，并整理了游戏崩溃与防护审计笔记。

### 3. 调试宏、作用域和输入输出

练习 20 中，我学习了 `dbg.h` 里的 `debug`、`log_err`、`check`、`check_mem` 和 `sentinel` 等宏，理解了它们如何统一输出错误信息并跳转到 `error` 标签清理资源。

练习 21～22 让我进一步区分了基本类型、函数作用域、文件作用域、`static`、`extern` 和 `const`。我也通过 `ex22.c`、`ex22.h` 和 `ex22_main.c` 实践了头文件声明与跨文件链接。

练习 24～25 主要涉及标准输入输出、文件读取和变参函数。我实现了基于格式字符串的读取函数，并扩展了一个简化版输出函数。这个过程让我更清楚地理解了 `FILE *`、`fgets`、`fscanf`、`va_list`、`va_start`、`va_arg` 和 `va_end` 的配合方式。

## 四、当前代码检查结果

目前主体代码已经能够构建和运行，但仍有一些需要继续完善的地方：

5. 不是每个教材章节都有独立的 `exN.c` 文件。有些章节属于环境准备、阅读、Makefile 或测试工程；最终提交时需要结合代码、笔记和测试结果说明学习过程，不能只按文件数量判断完成度。

## 五、学习收获与反思

完成 E3 后，我最大的变化是开始用“工程”的方式看待 C 程序。以前更关注一段代码能不能输出正确结果，现在会进一步考虑：文件如何组织、头文件如何声明、对象文件如何链接、资源由谁释放、错误如何返回、边界情况如何测试，以及出现崩溃后怎样定位。

Linux 命令行工具也不再只是零散的命令。Shell、Vim、Make、GDB、Valgrind、tmux 和 Git 可以组成一条完整的开发流程：在终端中编辑代码，用 Makefile 构建，用测试检查行为，用调试工具定位错误，再通过 Git 保存清晰的修改历史。

目前 E3 的主要学习内容已经完成，链表与库项目也通过了当前测试。后续我还需要修正总 Makefile 和剩余编译警告，并继续在后面的项目中使用这些工具，而不是学完之后就放在一边。
