## 5. 用户反复困惑的概念与有效解释

### 5.1 一个always为何有多个触发器

`out <= in`只描述一级采样，不能自动代表图中的四个DFF。最有效的解释是逐级写 `q0<=in; q1<=q0; q2<=q1; q3<=q2;`，再列单个1经过四个采样沿的状态表，最后才压缩成拼接。

### 5.2 state与next_state

用D触发器类比：`next_state=D`，`present_state=Q`。

- 组合块 `next_state=present_state` 是默认D=Q，表示保持。
- 时序块 `present_state<=next_state` 是时钟沿Q采样D。
- 复位修改Q，即present_state，不是next_state。
- 同一个状态变量不要在组合块和时序块同时赋值。

实际报过 `multiple constant drivers for next_state`，原因就是组合块赋next_state，复位块也赋next_state。

### 5.3 常量、位下标与输出不是一回事

- `parameter D=3` 用于独热位下标，`state[D]`是state[3]。
- D的完整独热编码是1000，不是3；`state==D`会错误比较到0011。
- `state==state[D]`是整向量与一位比较，不是判断是否处于D。
- 更清楚可命名 `D_BIT=3` 与 `STATE_D=4'b1000`。
- Lemmings中 `LEFT=0` 是编码；`walk_left=(state==LEFT)` 是输出。当state为LEFT时walk_left反而是1，因此不能用输出作为复位编码。

### 5.4 reg/wire与parameter/localparam

在Verilog-2001例子中：过程块赋值的位向量用reg，连续赋值/连接通常用wire。reg不自动等于触发器，组合next_state也可以声明reg。

parameter供实例化时配置；localparam用于模块内部不允许直接覆盖的常量。教材用parameter定义状态合法。没有依据声称一生一芯统一要求localparam。用户可以继续沿用教材，需讲清语义而不是制造“工程写法优越感”。

### 5.5 二维坐标、计数宽度

生命游戏统一使用 `(row,col)`，约定左上角(0,0)，`q[row*16+col]`。上下改变row，左右改变col，边界0与15环绕。

neighbor_count是一个0～8的数字，不是4个邻居。4个位权为8、4、2、1；`{3'b000,q[index]}`把每个邻居扩成4位的0或1，高三位不是另三份数据。

## 6. 蓄水池题：必须保留的准确资料

端口 `s[3:1]` 的顺序是 `{S3,S2,S1}`。正常有效读数只有：

```text
000：低于S1
001：S1～S2
011：S2～S3
111：高于S3
```

**旧记忆警告**：本轮读取全局MEMORY.md发现一个旧条目误写为111/110/100/000。那是错误的位序描述，不要沿用。本轮题目、波形和用户确认支持上面的000/001/011/111。主记录与本交接书已使用正确值；没有越权修改全局记忆。

六状态输出，顺序统一 `{fr3,fr2,fr1,dfr}`：

| 状态 | 输出 |
|---|---|
| low | 1111 |
| m1_u | 0110 |
| m1_d | 0111 |
| m2_u | 0010 |
| m2_d | 0011 |
| high | 0000 |

完整转移表见主记录21.3。读数保持时保留上升/下降历史；补充流量是额外进水，不是放水。低位最大进水，高位全部关闭，同步高有效reset进入low。

允许一次采样跨区间，因此low收到111可以直接进入high。未列出的异常传感器组合选择保持，是实现策略而不是题目明确规定。

## 7. 当前Lemmings 1的准确接续点

用户原始片段：

```verilog
parameter LEFT = 0, RIGHT = 1;
reg state, next_state;

always @(*) begin
    next_state = state;
    case (state)
        LEFT: if (bump_left) next_state = RIGHT;
        RIGHT: if (bump_right) next_state = LEFT;
        default: next_state = state;
    endcase
end

always @(posedge clk or posedge areset) begin
    if (areset)
        state <= walk_left; // 错在这里：应为LEFT
    else
        state <= next_state;
end

assign walk_left = (state == LEFT);
assign walk_right = (state == RIGHT);
```

已给出的修正：复位改 `state <= LEFT`，default可选择LEFT作为异常恢复。当前方向的碰撞触发翻转，两侧同时碰撞时原逻辑也会翻转，无需额外分支。用户已确认该题通过。

不要再把walk_left说成输入。`bump_left`是输入，`LEFT`是状态编码常量，`walk_left`是输出。

## 8. 避免继承对话中的过度断言

- 独热组合题会测试非独热输入，`out=state[D]`不能随意替换成 `state==4'b1000`；两者只在合法独热输入下等价。
- 4位结果赋值上下文会影响加法表达式宽度，不能说“8个1位信号直接相加一定只按1位计算”。显式补0是清晰的写法，不等于所有其他写法必错。
- 组合always中全部状态位无条件赋值时，开头清零可冗余；不要把 `next_state=0` 讲成FSM先进入一个全零状态。
- 非阻塞赋值在同一时间步的NBA更新阶段生效，不是隔一个完整时钟才执行；它保证连续采样逻辑使用更新前值。
- Moore输出由状态决定，不保证物理组合输出绝无毛刺。
- Quartus报约2147MB内存耗尽是真实报错；后发平衡树版本通过是用户明确确认的结果。但“根因一定是长加法链”“确定是32位进程上限”“所有类似错误都能靠平衡树解决”仍未经验证。
- 本轮没有逐题本地编译或收集通过截图。应接受用户明确报告的通过结果（Lemmings 1、生命游戏），但对其他题不能把“找到一个错误”自动提升成“全部测试通过”。
- 教材单always状态机模板的阻塞赋值不能只机械换一个符号；应同时处理输出依赖。后续继续以清晰的三段式和单驱动原则讲解。
