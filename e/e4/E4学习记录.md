更新时间：2026-10-01

## 一、学习目标

E4 的目标是从“写 C 程序”转到“写 RTL 电路”。核心是掌握一条完整链路：用 Verilog 描述电路，用 Verilator 把电路编译成可执行的 C++ 仿真程序，运行仿真、生成波形、并用 NVBoard 虚拟板卡做交互验证。

与 E3 最大的不同是引入了**结构化建模**这一约束：不用 `always` 行为建模，只用“实例化 + 连线”和 `assign` 描述电路。这是本阶段需要反复训练的技能。

我的 RTL 练习代码放在 WSL 的 `/home/ysyx/ysyx-workbench/npc`；Windows 文档放在 `E:\ysyx\e\e4`。

## 二、Verilator 仿真环境

### 1. 安装

从 git 安装 Verilator 的 stable 版本，安装在 `~/tools/verilator-stable`，**放在 `ysyx-workbench` 目录之外**——否则 git 会去追踪 Verilator 的源码，占用磁盘。

安装后确认：

```bash
which verilator        # /usr/local/bin/verilator
verilator --version    # Verilator 5.050 2026-07-01
```

### 2. 理解工作流

Verilator 不是解释器，它把 Verilog **翻译成 C++ 类**：`module top` 生成类 `Vtop`，模块的端口变成这个类的成员变量（`input a` → `top.a`，`output f` → `top.f`）。仿真程序就是操作这个类的实例：给成员赋值（喂输入）、调用 `eval()`（让电路重新计算）、读取成员（取输出）。

完整流程：

```text
vsrc/*.v + csrc/*.cpp  ──► Verilator ──► build/obj_dir/Vtop（可执行文件）──► 运行 ──► wave.fst
```

### 3. npc 项目结构

```text
npc/
├── Makefile          构建脚本（sim / wave / lint / clean 等规则）
├── .gitignore        白名单模式：只追踪源码，忽略 build/
├── csrc/main.cpp     仿真驱动
├── vsrc/*.v          RTL 源码
├── constr/*.nxdc     约束文件（NVBoard 引脚绑定用）
└── build/            编译产物（可随时删除重建）
```

`.gitignore` 用白名单写法（先忽略一切，再放行 `.v`、`.cpp`、`.h`、`Makefile` 等源码类文件），所以只有源码进版本库，`build/` 里的产物永远不进 git。

## 三、组合逻辑与波形

### 1. 双控开关

第一个电路是双控开关，两个输入异或后驱动一个输出：

```verilog
module top(
    input  a,
    input  b,
    output f
);
    assign f = a ^ b;
endmodule
```

`assign` 是数据流建模——把 `a` 和 `b` 的异或结果连到 `f`。

### 2. 仿真驱动 main.cpp

`main.cpp` 遍历 `a`、`b` 的全部四种组合，每次 `eval()` 后打印输出并用 `assert` 检查：

```cpp
for (int a = 0; a <= 1; a++) {
    for (int b = 0; b <= 1; b++) {
        top.a = a;
        top.b = b;
        top.eval();                          // 让电路重新计算
        std::printf("a=%d b=%d f=%d\n", a, b, (int)top.f);
        assert(top.f == (a ^ b));            // 自动检查
    }
}
```

我没有用参考实现的随机输入，而是穷举了四种组合——覆盖更完整。

### 3. 波形

用 `VerilatedFstC` 记录波形，输出到 `build/wave.fst`：

```cpp
VerilatedFstC trace;
top.trace(&trace, 99);
trace.open("build/wave.fst");
// 每次 eval 后：
trace.dump(context.time());
context.timeInc(1);      // 时间前进一格
```

用 GTKWave 打开 `wave.fst`。一开始看到信号的离散间距很大、以为没有变化，后来把光标在四个时间点移动、逐个读值，确认 `f` 依次是 `0 → 1 → 1 → 0`，与四种输入组合一致。

GTKWave 里的读法：左侧 Signals 面板是电路所有信号的清单，Waves 面板是你实际添加查看的信号；光标处的值显示为“信号名=当前值”。波形里 1 位信号高电平画在上方、低电平画在下方。

## 四、NVBoard 虚拟板卡

### 1. 安装与示例

NVBoard（NJU Virtual Board）是基于 SDL 的虚拟 FPGA 开发板，支持 LED、七段数码管、拨码开关、UART、键盘和 VGA。

```bash
cd ~/ysyx-workbench
bash init.sh nvboard
sudo apt install libsdl2-dev libsdl2-image-dev libsdl2-ttf-dev
```

环境变量 `NVBOARD_HOME` 需要自己写入 `.bashrc`（我一开始 `echo $NVBOARD_HOME` 为空，重载 shell 后正常）。

先运行官方示例确认环境：

```bash
cd ~/ysyx-workbench/nvboard/example
make run
```

窗口里能看到数码管、按键、LED（15~0）、开关（SW）、VGA 显示区域和 PS/2 键盘。

### 2. 工作原理

NVBoard 通过**把 Verilog 端口绑定到板子引脚**来工作，涉及三个东西：

```text
① 约束文件 .nxdc        （手写：端口 → 引脚）
        │  python auto_pin_bind.py
        ▼
② auto_bind.cpp         （自动生成：nvboard_bind_all_pins 函数）
        │
        ▼
③ main.cpp              （调 NVBoard 的 API）
```

约束文件格式：第一行 `top=模块名`，之后每行 `信号名 引脚名`，向量信号写成 `信号名 (引脚MSB, ..., 引脚LSB)`。

`auto_pin_bind.py` 把它转成 C++ 绑定函数：

```cpp
void nvboard_bind_all_pins(Vtop* top) {
    nvboard_bind_pin( &top->sw,   2, SW1, SW0);
    nvboard_bind_pin( &top->ledr, 1, LD0);
}
```

NVBoard 的四个 API：

```c
nvboard_bind_all_pins(dut);   // 绑定引脚
nvboard_init();               // 初始化（开窗口）
nvboard_update();             // 每个周期更新：读开关、刷 LED
nvboard_quit();               // 退出
```

### 3. 引脚表（N4 板卡）

从 `nvboard/board/N4` 查得。`input` 表示板子→电路，`output` 表示电路→板子：

| 组件 | 引脚名 | 方向 | 数量 |
|---|---|---|---|
| 拨码开关 | `SW0`~`SW15` | input | 16 |
| 按键 | `BTNC` `BTNU` `BTND` `BTNL` `BTNR` | input | 5 |
| LED | `LD0`~`LD15` | output | 16 |
| 数码管 | `SEG0A`~`SEG7P` | output | 8 管 × 8 段 |
| VGA | `VGA_VSYNC` `VGA_HSYNC` `VGA_BLANK_N`、`VGA_R0-7`、`VGA_G0-7`、`VGA_B0-7` | output | — |
| PS/2 | `PS2_CLK` `PS2_DAT` | input | 2 |
| UART | `UART_TX`(output) `UART_RX`(input) | — | 2 |

**没有 `clk`、没有 `rst` 引脚**：时钟由 `main.cpp` 的 `single_cycle()` 翻转产生，复位由 `reset(n)` 函数做。所以不接板子的端口（clk、rst）不写进 `.nxdc`。

### 4. 双控开关上板

顶层改成带 `clk` 的版本（NVBoard 的循环需要时钟）：

```verilog
module top(
    input       clk,
    input [1:0] sw,
    output      ledr
);
    assign ledr = sw[0] ^ sw[1];
endmodule
```

约束文件 `constr/top.nxdc`：

```text
top=top

sw (SW1, SW0)
ledr LD0
```

拨动 `SW0`、`SW1`，`LD0` 按异或规律亮灭。**这一步走通了完整的“电路 → 约束 → 绑定 → 交互”链路。**

（补记：当时以为的 `make run` 其实并没有真的运行程序——详见第七节的说明。现象是直接运行构建出来的 `build/top` 确认的；`make run` 的配方现在已经补上，可以正常用。）

## 五、时序逻辑：流水灯

流水灯是一组 LED 依次点亮并循环，是第一个时序逻辑电路。讲义给的参考实现用 `always`：

```verilog
always @(posedge clk) begin
  if (rst) begin led <= 1; count <= 0; end
  else begin
    if (count == 0) led <= {led[14:0], led[15]};
    count <= (count >= 5000000 ? 32'b0 : count + 1);
  end
end
```

行为是：`count` 每个时钟 +1，涨到 5000000 归零；每次 `count` 归零时，`led` 循环左移一位。`count` 用来降低移动速度，否则人眼看不见。

我**先用 `always` 实现并让 NVBoard 跑通**（现象正确），但这不是 ysyx 要的写法。**下一步：自己用 `Reg` 把 `vsrc/light.v` 从 `always` 改写成结构化建模**（代码自己写，这里只记思路和验收标准）。

### 改写思路

1. 先把 `always` 块里的东西分成两类：**状态**（`cnt`、`led`，需要被“记住”的值）和**“下一状态怎么算”**（纯组合逻辑）。
2. 每个状态用一个 `Reg` 实例：`din` 接“下一状态”，`dout` 接“当前状态”。`Reg` 的参数和端口是 `#(位宽, 复位值)` 与 `(clk, rst, din, dout, wen)`——原来 `if (rst)` 那个分支，就是靠 `复位值` 参数实现的。
3. “下一状态”用 `assign` 写成表达式。原来的 `if (cnt == 0) led <= 移位;` 要翻译成“当 `cnt == 0` 时取移位后的值，否则取 `led` 自己”——一个二选一。**这一步是整道题的关键**：想清楚“条件不成立的那一拍，`led` 应该等于什么”。
4. 想清楚 `wen` 该接什么：`always` 里“某些拍不更新”对应到硬件是什么？（提示：如果一个状态的下一状态在“不更新”时等于它自己，写使能就可以恒有效。）
5. 自检：改完之后 `vsrc/light.v` 里不应该再出现 `always`（`vsrc/template.v` 里的官方模板不算）。对照《E4 学习计划》第 5 节那五条规范和三个自检问题。

### 验收标准

- `make lint` 干净，`make run` 现象与现在一致；
- “现象一样”不等于“逐拍一样”。更可靠的做法是**改造前后逐拍对照**：把 `Reg` 版和 `always` 版放在同一个测试平台里同时例化，写一个 C++ 驱动（像 `csrc/main.cpp` 那样手动翻 `clk`、调 `eval()`），每个上升沿之后比较两者的 `led`，跑上千万拍零差异；
- 让这个对照跑得快的小技巧：把 `5000000` 提成参数（例如 `CNT_MAX`），默认值不变，验证时用 `CNT_MAX=4` 就能把换灯周期压到 5 拍，几纳秒跑完 16 次循环。这个技巧后面做 ALU、状态机、sCPU 都会用到。

## 六、触发器与选择器模板

结构化建模的基础是两个官方模板，放在 `vsrc/template.v` 中。

### 1. Reg 模板

带复位和写使能的寄存器：

```verilog
module Reg #(WIDTH = 1, RESET_VAL = 0) (
    input             clk,
    input             rst,
    input  [WIDTH-1:0] din,
    output reg [WIDTH-1:0] dout,
    input             wen
);
    always @(posedge clk) begin
        if (rst)      dout <= RESET_VAL;
        else if (wen) dout <= din;
    end
endmodule
```

实例化格式 `Reg #(位宽, 复位值) 实例名 (clk, rst, din, dout, wen);`。它内部含 `always`，但这是官方模板，使用者只负责实例化。

### 2. MuxKey 模板

键值选择器。`MuxKey` 无默认值（键找不到输出0），`MuxKeyWithDefault` 带默认值：

```verilog
MuxKey #(NR_KEY, KEY_LEN, DATA_LEN) 实例名 (out, key, lut);
MuxKeyWithDefault #(NR_KEY, KEY_LEN, DATA_LEN) 实例名 (out, key, default_out, lut);
```

`lut` 是查找表，把每对写成 `{键, 数据}` 再拼起来。例：

```verilog
MuxKey #(2, 1, 1) i0 (y, s, {
    1'b0, a,
    1'b1, b
});
```

当 `s=0` 输出 `a`，`s=1` 输出 `b`。状态转移可以用它写：

```verilog
MuxKeyWithDefault #(4, 2, 2) mux (
    next_state, current_state, 2'b00, {
        2'b00, 2'b01,
        2'b01, 2'b10,
        2'b10, 2'b00,
        2'b11, 2'b00
    }
);
```

### 3. 内部实现的理解

- **`Reg`**：`always @(posedge clk)` 描述的是触发器的时钟端——不是“一段程序”，而是“每来一个上升沿把 din 锁存到 dout”。`<=` 是非阻塞赋值，保证多个寄存器同一时钟沿同时更新。
- **`MuxKey`**：外层 `MuxKey` / `MuxKeyWithDefault` 都只是实例化 `MuxKeyInternal`，差别在参数 `HAS_DEFAULT`。`MuxKeyInternal` 用 `generate for`（编译期展开，把扁平的 `lut` 切成一对对）拆出 `key_list` 和 `data_list`，再用 `always @(*)`（组合逻辑）逐项比较：键匹配的那一项通过门控，其余为0，最后 OR 起来就是被选中的数据。因为键互不相同，最多一项命中。

## 七、工具链上发现并修掉的两个问题

1. **`make run` 原来是个空规则。** `npc/Makefile` 末尾写了 `.PHONY: default all clean run`，却从来没有 `run:` 的配方，`make run` 只会打印一行 `make: Nothing to be done for 'run'.`——**它什么都没跑，而且不报错**。也就是说以前记的“`make run` 后现象正确”里，`make run` 那一步其实没有生效（现象是直接运行构建产物 `build/top` 看到的）。已补上配方：

   ```makefile
   run: $(BIN)
   	@$^
   ```

   现在 `make run` 会先构建再启动 NVBoard；实测 `timeout 5 make run` 连续运行 5 秒无异常（退出码 124，表示是被 timeout 正常掐掉的，不是崩溃）。

2. **`lint` 规则改用 `--top-module`。** 原来为了压掉 `MULTITOP`（多个候选顶层，因为 `template.v` 里的模块没有被例化）加了 `-Wno-MULTITOP`；直接指定顶层更准确，也不再有“多个候选顶层”这回事：

   ```makefile
   lint:
   	verilator --lint-only -Wall -Wno-DECLFILENAME --top-module $(TOPNAME) $(VSRCS)
   ```

   `make lint` 通过，输出只有 Verilation Report，没有任何 warning。

## 八、南大实验二：译码器和编码器（阶段 D）

这是阶段 D 的第一个南大数字电路实验。验收任务是“实现一个 8-3 优先编码器并在数码管上显示”。我把它拆成五个器件逐个做，每个先仿真测试、再合起来上板。

### 1. 五个器件与实现方式

| 器件 | 映射类型 | 实现方式 |
|---|---|---|
| 2-4 译码器 `decode24` | 规律 | 先用 `MuxKey`，后可简化为 `<<` |
| 3-8 译码器 `decode38` | 规律 | `assign y = en ? (8'b1 << x) : 8'b0;` |
| 4-2 编码器 `encode42` | 不规律 | `MuxKeyWithDefault`（键=4位独热输入，数据=2位编号，默认 0） |
| 七段译码 `bcd` | 不规律 | `MuxKey`（键=BCD，数据=8位段码） |
| 8-3 优先编码器 `encode83` | 优先链 | `assign` 嵌套三元（从 `x[7]` 往下），`valid` 为 `x` 的归约或 |

关键判断：**“能不能用公式算出来”决定用 `assign` 还是 `MuxKey`**。译码器能算，编码器和数码管不能。

### 2. `MuxKey` 的几个要点

- `NR_KEY` 是**实际写了几对**，不是键空间大小（`2^KEY_LEN`）；两者不等时用 `MuxKeyWithDefault`。
- `lut` 是**一根很宽的单信号**，用位拼接 `{键, 数据, 键, 数据, ...}` 拼成，不是“列表”。
- `{键, 数据}` 顺序写反了不会报错，只会选错值。

### 3. 测试

每个器件都写了 C++ 驱动，**穷举所有输入**，期望值独立计算（不照抄 RTL 的表）。测试抓到过真实 bug：

- `encode42` 的循环上界写成 `x<8`（应为 `x<16`），漏测了 `x=8`（应输出 3）那一组。**“测试通过”不等于“覆盖完整”。**
- 2-4 译码器的 `lut` 里键 `100` 的数据误写成 `0000`（应为 `0001`）。

### 4. 上板与极性

NVBoard 的数码管是**共阳（低电平点亮）**。官方示例 `seg.v` 内部存“高电平点亮”的表，输出前用 `~` 取反。我的 `bcd.v` 一开始直接输出高电平表，上板会显示反的——**加 `~` 才对**。这类“极性”问题**仿真测不出来**（仿真只比你写的表），只有上板才暴露。

### 5. 验收现象

拨 `SW7~SW0`，结果：

| 输入 | LED2-0 | 指示位 LD4 | 数码管 |
|---|---|---|---|
| `00001110` | 011 | 1 | 3 |
| `10000000` | 111 | 1 | 7 |
| `00000001` | 000 | 1 | 0 |
| `00000000` | 000 | 0 | 0 |

第 3、4 组最能验证“编码位”和“指示位”是两条独立的线。

## 十、学习收获与反思

从 C 转到 RTL 最大的障碍是**思维方式**：Verilog 不是“一段会执行的程序”，而是“一张电路的描述”。一开始我按学 C 的习惯，用 `always` 加 `if/else` 去“写逻辑”，能跑通，但这不是 ysyx 要的方式。

理解 `Reg` 和 `MuxKey` 之后，思路变了：电路 = 寄存器（存状态）+ 组合逻辑（算下一个状态）。参考实现里一个 `always @(posedge clk)` 的 `if/else`，可以拆成“`Reg` 实例存当前值”加“`assign` 算下一个值”两部分——这个拆分就是结构化建模的核心，也是最需要亲手练的一步。

NVBoard 的接入让我第一次“看见”电路工作：拨开关、看灯亮，比只看波形直观。约束文件、自动绑定、`main.cpp` 的 API 调用三者配合，是一套可复用的验证流程，后面所有实验都建立在这套流程上。

一个方法论上的提醒：**“能跑通”和“改对了”是两件事**。改写之后现象一样可能只是碰巧，所以要有意识地做“改造前后逐拍对照”，而不是只看板子上灯在动。

另外，`make run` 那个空规则的坑也提醒我：Makefile 是“目标 + 配方”，只有 `.PHONY` 声明而没有配方时，make 会**安静地什么都不做**。以后每加一条规则，都要用 `make -n <目标>` 先看看它到底会执行什么。
