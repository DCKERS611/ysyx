```bash
gcc -std=c11 -Wall -Wextra -Werror -g source.c -o program

```

其中 `-Wall -Wextra` 开启常用警告，`-Werror` 将警告按错误处理，`-g` 保留调试信息，`-o` 指定输出文件。涉及数学库时在链接命令末尾加入 `-lm`；怀疑未定义行为时使用 sanitizer 辅助定位。

## 1. 程序的基本概念

来源：[第1章](https://akaedu.github.io/book/ch01.html)。教学主题：程序和编程语言、自然语言与形式语言、调试、第一个程序。

### 1.1 程序、语法与语义

程序是对计算步骤的明确描述。高级语言由编译器转换为机器可以执行的形式；C 源代码与可执行文件是两个不同对象。语法规定“怎样写才合法”，语义规定“这样写做什么”。编程语言不像自然语言那样容忍歧义，标点和大小写都可能改变含义。

### 1.2 第一个程序

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, Linux!\n");
    return 0;
}
```

`#include` 引入声明；`main` 是宿主环境中的 C 程序入口函数，实际由启动代码衔接调用；花括号形成函数体，分号结束语句。`\n` 表示换行，`return 0` 表示程序成功结束。

### 1.3 错误分层

- 编译诊断：缺分号、标识符未声明、类型不匹配等，先看第一条相关报错。
- 链接错误：例如找不到函数定义；与“缺少声明”不同。
- 运行时问题：非法内存访问等；不保证每次都会立即崩溃。
- 逻辑错误：能运行但结果不符合需求，靠输入、预期和实际结果比较定位。

建议练习：分别制造缺分号、拼错函数名、错误计算公式，判断错误发生在哪一步。每次只改一个因素。

## 2. 常量、变量和表达式

来源：[第2章](https://akaedu.github.io/book/ch02.html)。教学主题：Hello World 细节、常量、变量、赋值、表达式、字符编码。

### 2.1 类型、初始化与赋值

整数 `42`、浮点数 `3.14`、字符 `'A'`、字符串 `"A"` 属于不同形式。`'A'` 与 `"A"` 不能互换，后者包含字符和终止空字符。

```c
int count = 3;      /* 定义并初始化 */
count = count + 1;  /* 给已有对象赋值 */
```

`=` 是赋值，`==` 才是相等比较。局部自动变量没有初始化时不能当作已有确定值使用。标识符区分大小写，不能用关键字；名称要体现用途。

### 2.2 表达式与输出

```c
double a = 5 / 2;    /* 先做整数除法，结果为 2.0 */
double b = 5.0 / 2;  /* 浮点除法，结果为 2.5 */
```

结果类型由运算规则决定，不由接收变量倒推。优先级决定表达式如何组合；复杂表达式主动加括号。

常用 printf 格式：`%d` 对应 int，`%u` 对应 unsigned int，`%c` 输出字符，`%f` 输出 double，`%s` 输出以 NUL 结尾的字符串，`%%` 输出百分号。格式与实参类型必须匹配。

### 2.3 字符编码

`\n` 换行、`\t` 制表、`\\` 反斜杠、`\0` 空字符。ASCII 编码中可以用字符数值说明字符运算，但不要把一个字节等同于一个中文字符。UTF-8 中文通常占多个字节，`strlen` 统计字节数，不是视觉上的字符数。

建议练习：比较 `5/2` 与 `5.0/2`，用 `%c`、`%d` 分别打印同一个 ASCII 字符，解释输出差异。

## 3. 简单函数

来源：[第3章](https://akaedu.github.io/book/ch03.html)。教学主题：数学函数、自定义函数、形参与实参、全局/局部变量与作用域；本章还介绍 Man Page。

### 3.1 声明、定义和调用

声明描述接口，定义提供函数体，调用执行函数。使用数学函数应包含 `<math.h>`，Linux GCC 链接数学库时可写：

```bash
gcc -Wall -Wextra math_demo.c -o math_demo -lm
```

头文件提供接口信息，库提供实现。漏写 `<stdio.h>` 时，编译器没有收到正确的 printf 声明；较旧 GCC 可能报告隐式声明与内建声明不兼容。C99 起不允许隐式函数声明，不应依赖“警告后碰巧能运行”。C11 中 `int f(void)` 明确无参数，`int f()` 作为声明并不提供参数类型信息。

### 3.2 值传递：已讨论的 increment 题

```c
void increment(int x)
{
    x = x + 1;
}
```

`increment(i)` 复制 i 的值给 x，修改 x 不会修改 i。可改为返回计算结果，由调用者赋值：

```c
int increment(int x)
{
    return x + 1;
}
/* 调用：i = increment(i); */
```

也可传地址并通过指针修改原对象，见第23章。传指针仍然是值传递，复制的是地址值。

### 3.3 作用域与生存期

作用域描述名字在哪里可见，生存期描述对象何时存在，两者不是同一个概念。普通局部变量属于本次调用，递归调用有各自的局部对象。避免依赖大量全局变量传递状态；同名局部变量遮蔽外层名字时容易误读。

建议练习：预测 increment 调用前后的 i、x，再在各自作用域内打印验证。查 `man 3 printf` 的头文件、参数和返回值。

## 4. 分支语句

来源：[第4章](https://akaedu.github.io/book/ch04.html)。教学主题：if、if/else、布尔代数、switch。

- 条件中零为假、非零为真，负数也是真；关系和逻辑运算产生 int 类型的 0 或 1。
- `a < x && x < b` 表示区间判断，不能写成数学形式的 `a < x < b`。
- `&&`、`||` 短路求值；`p != NULL && *p > 0` 先检查指针再解引用。
- `!` 是逻辑非，`~` 是按位取反；`&&` 与 `&` 也不同。
- `else` 与最近的未匹配 if 结合，使用花括号明确结构。
- switch 的 case 使用整数常量表达式；没有 break 会继续落入后续分支，default 处理未匹配情况。

建议练习：实现成绩分类，并测试每个分界值前后；另用 switch 实现简单运算符选择，说明 break 的作用。

## 5. 深入理解函数

来源：[第5章](https://akaedu.github.io/book/ch05.html)。教学主题：return、增量式开发、递归。

### 5.1 返回值与分解问题

非 void 函数应在需要返回结果的所有路径上返回有效值。return 结束当前函数，不会只结束所在 if 或循环。把“计算”和“显示”分开：计算函数返回值，调用者决定怎样输出。

增量式开发：先确定接口和最简单可运行版本，再逐步加入计算，每一步用已知输入验证。原书通过距离与圆面积说明问题分解；不要一次写完大段代码后才首次编译。

### 5.2 递归

递归需要基础情况和向基础情况推进的步骤。例如阶乘以 `0! = 1` 为基础，每层处理 n 并调用 n-1。分析时分别跟踪进入调用和返回结果。

检查输入范围、整数溢出、递归深度；数学上的正确递推式不保证固定宽度整数计算始终有效。递归还可能重复计算，改用迭代或缓存可降低成本。

建议练习：用递归与循环各实现小范围阶乘，对比 0、1 和普通输入；为负数输入明确接口约定。

## 6. 循环语句

来源：[第6章](https://akaedu.github.io/book/ch06.html)。教学主题：while、do/while、for、break/continue、嵌套循环、goto。

- while 先判断，可能执行零次；do/while 先执行再判断，至少一次，末尾需要分号。
- for 顺序为初始化、条件、循环体、更新，再回条件；`for (;;)` 表示省略条件的无限循环。
- break 跳出最近一层循环或 switch；continue 跳过本轮剩余部分。
- for 中 continue 后仍执行更新表达式；while 中 continue 直接回到条件，注意是否漏掉变量更新。
- 嵌套循环分别管理各层变量和边界。goto 可用于函数内统一清理资源，不应随意跨越逻辑制造难以跟踪的流程。

循环检查四件事：初值、继续条件、更新方式、结束时应成立的性质。数组常用半开区间 `[0, n)`，避免 `i <= n` 访问越界。

建议练习：实现素数判断，处理 n<2；解释循环终止条件。编写读文件循环，分别处理正数、EOF 和错误，而不是只看真假。

## 7. 结构体

来源：[第7章](https://akaedu.github.io/book/ch07.html)。教学主题：复合类型、数据抽象、数据类型标志、嵌套结构体。

结构体把有关联的数据组织成一个整体；通过成员名表达含义，而不是依赖无说明的多个变量。

```c
struct point {
    double x;
    double y;
};

struct point p = {1.0, 2.0};
```

通过 `p.x` 访问成员。结构体可以整体赋值，也可以按值传入和返回；普通数组不能整体赋值。原书以复数表示说明抽象：对外描述“加法、乘法”等操作，内部表示可以是直角坐标或极坐标。

enum 可表示有限种状态或类型标志，减少魔法数字。结构体可以嵌套，访问形式如 `line.start.x`。不要假设结构体大小等于成员大小之和，布局可能包含对齐填充。

建议练习：定义 point 与由两个 point 构成的 line，写计算长度的函数；明确参数是复制结构体还是传地址。

## 8. 数组

来源：[第8章](https://akaedu.github.io/book/ch08.html)。教学主题：数组基础、随机数统计、直方图、字符串、多维数组。

### 8.1 元素、下标与统计

数组存储连续的同类型元素，下标从 0 开始。`int a[5] = {0};` 将全部元素初始化为零；未初始化的局部数组没有可依赖的初值。访问 `a[5]` 已经越界。

随机数统计把某个取值映射到计数数组下标，再把计数画成文本直方图。`rand` 是伪随机序列，`srand` 设置种子；不应每取一个数就重新设种子。简单取模可用于教学，但通常存在分布偏差，不用于安全随机数。

### 8.2 字符串和容量

```c
char text[] = "ABCDE"; /* 6 字节，包括 '\0' */
```

字符串内容长度为 5，数组容量为 6。`sizeof text` 获取整个数组字节数，`strlen(text)` 数到第一个 NUL，不计终止字节。read 不会自动添加 NUL；使用 `%s` 前必须确保缓冲区中有合法的字符串终止符。

### 8.3 多维数组

`int table[2][3]` 是包含两个“3个int组成的数组”的数组，按行连续存放。两层下标各有边界。把规则写入表格可减少重复条件分支，这是数据驱动的一种方式。

建议练习：统计数字出现次数；测试空字符串、刚好填满缓冲区的输入；用两层循环遍历矩阵。

## 9. 编码风格

来源：[第9章](https://akaedu.github.io/book/ch09.html)。教学主题：缩进和空白、注释、命名、函数划分、indent 工具。

- 缩进表达控制层次，空格帮助区分运算和参数。项目既有风格优先，不混用多套花括号规则。
- 注释说明目的、约束、边界或不直观的原因，不只重复代码字面意思。
- 名称体现单位和角色，例如 byte_count、capacity、fd；避免一个变量承担多种不相关用途。
- 函数职责集中，过深嵌套往往意味着需要提取函数或提前处理异常路径。
- 原书介绍 indent 自动排版；格式化只能统一外观，不能修复错误逻辑或不合理接口。

建议练习：整理一份自己已运行的程序，保持行为不变；比较整理前后是否更容易看到错误处理路径。

## 阶段实践总结

本阶段通过连续的小程序练习，将第 1–9 章的语法知识落实到编译、运行、测试和调试过程中。以下按知识主题总结主要实践与收获。

### 第一阶段：Linux 起步、程序与简单函数

- 能用 Man Page 的章节号区分命令、系统调用和库函数，例如 `printf(1)` 与 `printf(3)`、`write(2)`、`open(2)`。
- 能按 NAME、SYNOPSIS、RETURN VALUE、ERRORS 阅读接口，理解 `ssize_t` 返回的实际字节数、EOF、部分读写及 `errno`。
- 已用 `/dev/full` 验证写失败路径：`perror` 输出 ENOSPC，程序退出状态为 1；正常运行退出状态为 0。
- 理解文件描述符是进程打开文件表的索引，`open` 返回当前最小可用 fd，观察到的 3 不是固定规定。
- 能使用 `gcc -Wall -Wextra -Werror -g` 编译、`./程序` 运行、`echo $?` 查看退出状态；理解编译错误、链接错误、运行错误和逻辑错误的区别。
- 已分析遗漏 `<stdio.h>` 时 `printf` 缺少正确声明的问题；理解头文件提供声明，库或目标文件提供实现。
- 理解 C 按值传参：形参是本次函数调用中的局部变量，修改形参不会修改实参。局部变量作用域互不干扰，未初始化自动变量不能读取；全局对象默认零初始化。

### 第 4 章：分支语句

- 掌握零为假、非零为真；能正确写区间 `x >= 3 && x <= 8` 及其否定 `x < 3 || x > 8`。
- 知道 `0 < x < 10` 会按两次比较计算，不等价于数学链式不等式。
- 掌握 `&&`、`||` 的短路求值，能够解释为何 `x != 0 && y / x > 1` 可避免除零；区分逻辑或 `||` 与按位或 `|`。
- 掌握 `switch` 的 case、fall-through、break 和 default，已实现工作日/周末分类。
- 已定位过 `if` 后误加分号、赋值与相等比较混淆等典型控制流问题。

### 第 5 章：返回、增量开发与递归

- `return` 返回值并立即结束当前函数；非 void 函数的有效路径需要给出返回值。
- 实现闰年判断，验证 1900、2000 等边界。
- 逐步实现两点距离、圆面积和以两点距离为半径的面积，体会先做最小可运行版本再逐步组合。
- 实际遇到 `pow`、`sqrt` 的 `undefined reference`，通过把 `-lm` 放在源文件或目标文件之后完成数学库链接；区分“已经声明”与“链接到实现”。
- 识别全局 `double pi = acos(-1.0);` 在严格 ISO C 下不是常量表达式初始化，理解 GCC 扩展与 `-pedantic-errors` 的区别。

## 11. 排序与查找

来源：[第11章](https://akaedu.github.io/book/ch11.html)。教学主题：算法、插入排序、时间复杂度、归并排序、线性查找、折半查找。

### 11.1 排序

插入排序维持“前缀已经有序”，取下一元素，在前缀中移动较大元素后插入。通常最坏 O(n²)，接近有序时移动较少；使用适当比较方式可保持相等元素原顺序。

归并排序把区间分开排序，再合并两个有序段，时间复杂度 O(n log n)，常见数组实现需要 O(n) 辅助空间。真正要落实的是两个子区间边界、合并游标和剩余元素复制。

### 11.2 查找与契约

线性查找不要求有序，最坏 O(n)。折半查找要求数据按约定顺序排列，每轮舍弃一半，O(log n)。明确区间采用 `[lo, hi)` 还是 `[lo, hi]`，不能混用更新规则。

对于满足 `0 <= lo <= hi` 的索引，`lo + (hi - lo) / 2` 可避免直接相加的某些溢出问题。无符号索引要特别警惕 `mid - 1` 下溢。

契约包括前置条件、后置条件；assert 可检查程序内部假设，不应用于必须执行的文件打开等操作，因为定义 NDEBUG 后断言表达式可能不执行。

本章已完成七个程序练习：快速排序、最小值、次小值、快速选择、查找重复序列中第一次出现的位置、折半求平方根以及递归/迭代快速幂。快速选择中曾把右区间内的目标秩写成 `k-mid`，修正为减去左段及枢轴占据的秩；快速幂能够跟踪“指数最低位决定是否乘入结果、底数平方、指数折半”的迭代过程。

测试覆盖空数组约定、单元素、重复值、首尾命中和未命中。排序结果不仅检查是否有序，也检查元素是否丢失或增加。

## 12. 栈与队列

来源：[第12章](https://akaedu.github.io/book/ch12.html)。教学主题：数据结构、栈、DFS、队列与 BFS、环形队列。

栈后进先出，核心操作是 push/pop；队列先进先出，核心操作是入队/出队。要先约定 top、head、tail 分别指向“已有元素”还是“下一个空位”。学习中特别区分了两种栈：递归调用使用由编译器生成调用代码管理的函数调用栈；非递归 DFS 使用程序显式定义的数组栈和 `top`。

DFS 借助递归或显式栈深入，再回溯探索；BFS 借助队列逐层展开，在无权图中可寻找最少边数路径。迷宫搜索要记录已访问状态，必要时保存前驱用于还原路径。

环形队列用取模复用数组空间。若采用“空出一格”方案：

```text
head == tail                表示空
(tail + 1) % capacity == head 表示满
实际最多存 capacity - 1 个元素
```

也可单独维护元素个数，不能把不同方案的满/空判断混用。

已完成显式栈 DFS、递归 DFS 和环形队列 BFS。递归 DFS 在目标分支返回成功后，利用函数逐层返回的过程打印成功路径；BFS 使用稳定的访问记录保存前驱，因此可以还原无权网格中的最短路径。还验证了教材迷宫中队列容量为 5 时可运行、容量为 4 时失败，并解释了“空出一格”实现的实际可用容量为 `capacity - 1`。

## 14. 计算机中数的表示

来源：[第14章](https://akaedu.github.io/book/ch14.html)。教学主题：二进制、进制转换、原码/反码/补码、有符号与无符号、浮点数。

### 14.1 位模式和解释

同一个位模式按不同类型解释，数值可能不同。n 位无符号数范围是 0 到 2ⁿ−1；采用补码时，n 位有符号数范围是 −2ⁿ⁻¹ 到 2ⁿ⁻¹−1。

### 14.2 溢出与浮点数

C 中无符号算术按类型范围取模；有符号整数溢出属于未定义行为，不能把“硬件会绕回”当成语言保证。

## 15. 数据类型详解

来源：[第15章](https://akaedu.github.io/book/ch15.html)。教学主题：整型、浮点型、整数提升、通常算术转换、赋值转换、强制转换、编译器处理。

### 15.1 类型宽度

char、short、int、long、long long 的大小受实现影响；`sizeof(char)` 恒为 1，但 C 的一个字节位数由 CHAR_BIT 表示。当前常见 Linux 字节为 8 位，仍应查 `<limits.h>` 和 `<stdint.h>`，不能照搬原书所有大小表。

`size_t` 用于对象大小，输出用 `%zu`。`ssize_t` 是 POSIX 有符号类型，read/write 用它表示字节数或 -1；在 POSIX 环境中通常用 `%zd` 输出。严格 ISO C 可移植代码应另行处理 POSIX 类型。

### 15.2 隐式转换

char、short 等参与运算常先提升到 int，必要时提升到 unsigned int；之后依据通常算术转换统一操作数类型。

```c
int a = -1;
unsigned int b = 1;
/* a < b 为假：比较前 a 转为 unsigned int。 */
```

赋值转换发生在右侧表达式算完之后。`(double)(5 / 2)` 得到 2.0，`(double)5 / 2` 得到 2.5。强制转换不检查业务合理性，也不能修复已发生的越界、溢出或错误指针。

## 16. 运算符详解

来源：[第16章](https://akaedu.github.io/book/ch16.html)。教学主题：位运算、移位、掩码、异或、复合赋值、条件与逗号运算符、sizeof/typedef、副作用与序列点、运算符总结。

### 16.1 位操作

在常见的 32 位 unsigned int 环境中，对合法位号 k：

```c
unsigned int mask = 1u << k;
x |= mask;             /* 置位 */
x &= ~mask;            /* 清位 */
x ^= mask;             /* 翻转 */
/* (x & mask) != 0：检查该位是否为 1 */
```

移位量不得为负或达到提升后左操作数的位宽。位运算优先使用无符号类型；不要依赖 C11 中负数右移的可移植结果，也不要用有符号左移制造溢出。通过教材示例区分了无符号右移高位补零与负的有符号整数右移属于实现定义。

已实现并验证：

- `countbit`：逐轮检查最低位并右移，统计无符号整数中 1 的数量；
- `multiply`：根据乘数最低位决定是否累加被乘数，再同步左移被乘数、右移乘数，实现无符号移位加法乘法；
- `rotate_right`：使用 `(x >> n) | (x << (width - n))` 合并互不重叠的位段，并用 `n %= width` 处理超过位宽的旋转次数；
- XOR 校验：利用 `A ^ B ^ A = B` 解释 RAID 5 单盘故障时的校验恢复；
- 无临时变量交换：比较 XOR 法和加减法，认识到同一对象别名及有符号溢出的局限。

### 16.2 其他运算符

`x += y` 对左操作数只求值一次；`condition ? a : b` 根据条件只求值一个分支。逗号运算符依次执行两个表达式，整个表达式采用右侧的值；函数实参之间的逗号只是分隔符。

sizeof 通常不求值其操作数，但变长数组相关情形有例外。typedef 定义类型别名，不创建变量，也不是简单文本替换。

### 16.3 副作用与求值顺序

优先级和结合性不等于运行时求值顺序。避免 `i = i++`、`printf("%d %d", i++, i++)` 等未排序的冲突访问，它们在 C11 中属于未定义行为。

原书用 Sequence Point 讲解，现代标准还使用 sequenced before 等术语。已通过后缀自增、短路逻辑和逗号运算练习判断副作用的先后关系；能够说明 `int x = i++` 结果确定，而 `i++ + i` 存在未排序的冲突访问。运算符总结中进一步区分了优先级、结合性和实际求值顺序，并识别 `x & mask == 0` 会被错误组合为 `x & (mask == 0)`。

## 23. 指针

### 23.1 指针层级、数组和 const

指针保存对象地址，解引用访问所指对象；C 的参数传递仍然是值传递，指针参数复制的是地址值。需要修改调用者的指针变量本身时，要继续传入该指针变量的地址，例如链表头指针使用 `Node **`。

能够从类型和寻址两种角度展开多级指针表达式，并区分 `char **const p`、`char *const *p`、`const char **p` 等声明中被 const 限制的层级。指针加减按所指类型的宽度移动；两个指针只有在同一数组及其尾后位置范围内进行关系运算或相减才具有相应语义。

已经区分：

```c
int *a[10];    /* 含10个int *元素的数组 */
int (*p)[10];  /* 指向含10个int元素的数组的指针 */
```

数组名在多数表达式中转换为首元素指针，但在 `sizeof`、取地址以及字符串字面量初始化字符数组等场景不能简单套用该规则。多维数组的指针运算取决于每一层所指数组类型，不能把所有地址都按一维元素宽度理解。

### 23.2 函数指针、结构体和动态内存

能够读写函数指针声明，使用 typedef 为函数指针类型命名，并理解函数名在调用接口中的转换。复杂声明按变量名附近开始、结合括号逐层向外阅读。

结构体可以通过指针引用同类型结点，但不能直接包含自身对象，否则对象大小无法确定。`void *`可以保存对象地址，但解引用或进行标准 C 指针算术前必须先转换为具体对象指针类型。

掌握 `malloc`、`calloc`、`realloc` 和 `free` 的基本约定。动态内存的地址不等于数组长度，长度需要由程序另外保存和传递；释放后不能继续解引用，不能重复释放，同一所有权也不能被多个清理路径重复处理。

## 24. 函数接口与程序构建

### 24.1 编译器与链接器

编译器以翻译单元为单位检查语法和类型并生成目标文件；链接器解析跨目标文件的符号引用，把目标文件和库组合成最终程序。缺少声明通常首先表现为编译诊断，只有声明而没有可用定义则常在链接阶段出现未定义引用。

声明描述名称及类型，定义还提供对象存储或函数实现。`static`、`extern`、文件作用域和块作用域会影响名称可见性、链接属性与对象生存期。头文件用于共享声明，应使用头文件保护，定义通常放在源文件中，避免多个翻译单元重复定义。

### 24.2 数组参数和接口契约

数组传给函数后通常只传递首元素地址，函数不能通过该指针恢复原数组长度。因此常见接口需要同时传入数组和元素数量；宏只能在仍能看到完整数组类型的调用位置计算元素数量，typedef、static 或全局变量都不会让普通指针自动携带长度。

函数接口要明确参数是否允许为空、缓冲区容量、返回值含义、所有权转移以及错误表示。返回值和 `errno`各有约定，不能在调用成功后把旧的 `errno`当作本次错误。

## 25. C 标准库

### 25.1 字符串与内存块

C 字符串以 NUL 字节结尾，数组容量必须包括终止字节。`strlen`统计终止字节之前的字符数，不包括 NUL；按字节复制时是否包含 NUL 取决于显式给出的长度。

`memcpy`适用于不重叠内存块，重叠时使用 `memmove`；两者按字节复制，不负责识别字符串边界。`strcmp`返回负、零、正表示字典序关系，不能依赖其绝对返回值。学习了 `strchr`、`strtok` 等接口，其中 `strtok`会修改原缓冲区并保存内部状态，后续传入 NULL 表示继续处理同一轮剩余内容，而不是让 NULL 指向某个字符串。

### 25.2 文件流与格式化转换

掌握 `fopen`、`fclose`、`fgetc`、`fgets`、`fprintf`、`fscanf`、`fread`、`fwrite`、`feof`、`ferror` 和 `rewind` 等基本接口。读取函数的返回值决定本次是否取得数据，不能用 `while (!feof(fp))`预测下一次读取成功。

`fread`和`fwrite`按“每组大小 × 组数”处理原始字节，返回成功完成的组数；字符、图片和视频在文件中最终都是字节序列，函数不会为不同媒体自动解释内容。格式化输入依赖文件格式和转换说明，若不知道数据布局，必须先定义或识别文件格式，不能仅凭目标变量类型猜测。

标准输入、标准输出和标准错误通常对应文件描述符 0、1、2。Shell 中 `>`重定向标准输出，`2>`重定向标准错误；`perror`写标准错误流。能够解释文本流位置、EOF、部分读写以及文件被读过后通过 `rewind`或定位函数重新读取。

`strtol`除返回转换结果外，还通过结束指针指出解析停止位置，因此可以区分完整转换、部分转换和没有数字可转换等情况。

### A.2 read/write 与缓冲区

```c
ssize_t read(int fd, void *buf, size_t count);
ssize_t write(int fd, const void *buf, size_t count);
```

fd 表示去哪个已打开对象，buf 表示内存位置，count 表示最多请求的字节数。read 从 fd 写入 buf，write 从 buf 输出到 fd。正返回值表示实际传输的字节数，可能少于 count；-1 表示错误。

对普通文件、非零 count 的 read，返回 0 表示当前位置到达 EOF。若 count 为 0，read 也可以直接返回 0，不能因此判断 EOF。成功调用可能留下旧 errno。

write 输出字节数不等同于 Unicode 字符数；printf 对普通窄字符输出也不能把返回数量理解为中文字数。

把 read 的数据作为字符串显示时：留出 NUL 容量，先检查 n 是否负数，再写 `buffer[n] = '\0'`。这种显示适合没有内嵌 NUL 的文本片段，不是通用二进制输出方式。

以文件内容 ABCDEFGHIJKL 为例，每次请求 5 字节时，顺序读取的返回值应为 5、5、2、0；最后一次返回 0 表示到达 EOF。

### A.3 文件位置与 open

`open("data.txt", O_RDONLY)` 成功返回非负 fd，失败返回 -1。实验中首次获得 fd 3；如果标准描述符已关闭，也可能返回 0、1 或 2，因此不能用 `fd <= 0` 判断失败。

SEEK_SET 从文件开头计算，SEEK_CUR 从当前位置计算，SEEK_END 从文件大小计算。lseek 成功返回新偏移，失败为 `(off_t)-1`；后续 read 从新位置继续。相对文件名基于进程当前工作目录，而不一定是源文件目录。

### A.4 实际验证过的 Shell 错误

`echo$?` 少空格会展开为 echo0 等命令名，找不到命令返回 127。随后执行 `echo $?` 得到的是这条失败命令的状态。需要立刻保存 `status=$?`。

曾将 `mv data.txt data.txt.bak` 误写为 `mv data,txt data.txt.bak`，逗号导致源文件不存在，因此原文件没有移动，随后 open 仍能成功。纠正文件名后，程序进入预期的打开失败路径。

```bash
./demo > /dev/full
status=$?
echo "$status"
```

向 `/dev/full` 写入时，程序输出 `write: No space left on device` 并以状态 1 结束。ENOSPC 表示设备空间不足，不是内存不足；`/dev/full` 是用于模拟此错误的特殊设备，不说明真实磁盘已经满。

`>` 重定向 stdout，`2>` 重定向 stderr。perror 写 stderr，因此只重定向 stdout 时错误仍显示在终端。/dev/full 的 major=1、minor=7 是设备编号；读取提供零字节内容，seek 成功不代表后续 write 成功。
