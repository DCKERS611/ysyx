## 3. 下一窗口的唯一接续点

不要重讲第 21 章，也不要重新从普通指针开始。先用清晰的内存/类型视角区分：

```c
int *a[10];    /* a 是数组，含 10 个 int * 元素 */
int (*p)[10];  /* p 是指针，指向含 10 个 int 元素的数组 */
```

然后做教材第 23 章第 7 节附近的多维数组指针题。题目必须把下面的完整声明原样给出，再让用户分别用 `pa` 和 `ppa` 访问字符 `'r'`：

```c
char a[4][3][2] = {
    {{'a', 'b'}, {'c', 'd'}, {'e', 'f'}},
    {{'g', 'h'}, {'i', 'j'}, {'k', 'l'}},
    {{'m', 'n'}, {'o', 'p'}, {'q', 'r'}},
    {{'s', 't'}, {'u', 'v'}, {'w', 'x'}}
};

char (*pa)[2] = &a[1][0];
char (*ppa)[3][2] = &a[1];
```

供教学者核对的结果是 `pa[5][1]` 和 `ppa[1][2][1]`，但出题时不要提前告诉用户。做完后继续函数指针以及不完整/复杂声明，再进入第 24 章。

## 4. 已掌握但容易混淆的关键点

### 4.1 预处理与宏

- 宏是预处理阶段的记号替换，不是函数。
- 函数式宏必须充分加括号；宏形参出现多次会让有副作用的实参被求值多次。
- 多语句宏通常用 `do { ... } while (0)` 包装，使其在语法上像一条语句。
- `#` 用于字符串化，`##` 用于连接记号；条件编译中 `#if` 判断表达式，`#ifdef` 只判断是否定义。
- 用户已经做完相关判断题，不要再次用缺失宏定义的表达式单独出题。

### 4.2 指针

- C 仍然是值传递；指针参数复制的是地址值，但通过解引用可以修改调用者对象。
- `p + 1` 按所指类型跨过一个元素，不是简单增加一个字节。
- 同一数组中的指针相减得到元素间距，类型为 `ptrdiff_t`，常用 `%td` 输出。
- `const char **p`、`char *const *p`、`char **const p` 的 const 所在层级不同。判断时先读最靠近变量名的部分，再逐层向外读。
- `char **const p` 中 `p++` 非法，`(*p)++` 和 `(**p)++` 合法。用户已经修正并理解这一点。

## 7. 教学与沟通要求

1. 每道题必须给出完成解题所需的全部声明、宏定义、初值和代码上下文。不能只给 `REST(x++, y++)` 却不说明 `REST` 的定义。
2. 出题后等待用户回答，不要紧接着自问自答。讲解答案时先复述准确表达式，再逐步展开。
3. 避免“第一组、第二组、前者、后者”这类脱离代码就不明确的说法；应重复完整声明或为选项明确编号。
4. 用户要求“给代码”时，直接在聊天中给出完整、短行、便于 Vim 粘贴的代码。除非用户明确说“帮我创建文件”，不要在 WSL 中新建或修改练习文件。
5. 用户已有基础，简单内容可以直接做题；遇到“不会”“不理解”时，再用具体数组、下标、地址变化或一轮执行过程详细解释。
6. 不必反复提醒 `main` 的细枝末节，除非确有编译、运行或未定义行为问题。
7. Vim 粘贴曾多次造成缩进和截断困扰。代码尽量避免过长行，并优先提供完整、可一次复制的代码块。
8. 提到“栈”时必须标明是“函数调用栈（由编译器生成的调用代码管理，位于操作系统提供的线程栈内存中）”还是“程序手写的数据结构栈（如 `stack[]`、`top`）”。
9. 学习报告是面向老师的成果文档，不写聊天过程、内部操作流水账或无关的环境检查经过。
