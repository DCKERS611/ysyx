# E5 DiffTest：C 风格学习版

先读 `difftest_cstyle.cpp`。这是可运行的 E5 教学入口，保留逐条比较的核心流程，把原版的容器、字符串拼接和期望文件解析拿掉。

## 1. 文件与范围

| 文件 | 用途 |
|---|---|
| `difftest_cstyle.cpp` | 主学习文件：装载、初始化、单步、比较、退出 |
| `reference_bridge.h` | EMU 的普通函数接口和普通结构体 |
| `reference_bridge.cpp` | 把原有 EMU 类封装起来，初读可以跳过 |
| `Makefile` | 单独构建，复用 `../../e5` 的 RTL、仿真支持和参考模型 |

本版针对 **E5**：PC 从 0 开始，参考内存 1024 字节，最多 1000 步。不能直接用来跑 E6 的 AM 镜像。E5 原版与 WSL 当前 E6 文件都没有被修改。

它仍需 C++ 编译器，因为 Verilator 输出的是 C++ 类。学习文件中的算法使用 C 风格：结构体、指针、普通函数、显式类型、固定字符数组、for/while 和 printf。不要求先理解 STL、lambda 或模板。

## 2. 先读 main 的四段

1. `ref_load`、`pmem_load_file`：两边从同一个 bin 分别装载，内存各自独立。
2. 创建硬件模型，清零测试用寄存器初态，复位 PC。
3. 每次循环：保存旧 PC/指令/读口值 → NPC 一拍 → EMU 一条 → 比较。
4. 确认 ebreak，比较内存，再返回进程结果。

先只读 main，不用立即展开辅助函数。读到 `compare_step()` 时，把它理解成“检查两边这条指令算得是否相同”。

## 3. 再读两个比较函数

`check_value()` 收到：计数器地址、检查项名称、实际值、期望值。相同只计数；不同就计数并打印。

`compare_step()` 会检查：执行前 PC 和指令、非法指令判断、是否接受执行、执行后 PC、16 个寄存器、实际源寄存器读口、结束状态。一次调用会检查完当前指令全部项目，再决定停止，不需要 vector 暂存差异。

ebreak 当步特殊处理：NPC 仍更新 PC，EMU 保持 PC，所以不比较结束后的 PC，而是比较执行前 PC 和 halt_pc。

`compare_memory()` 在结束时比较完整 1024 字节内存，防止只改变内存而没有读回的 store 错误漏检。

## 4. 这里出现的指针和 C++ 接口

```cpp
struct Check check = {0, 0};
check_value(&check, "pc", actual, expected);
```

`&check` 取地址。函数收到 `struct Check *check` 后，通过 `check->total++` 修改调用者的计数器。没有复制一份局部计数器。

```cpp
VerilatedContext context;
Vtop npc(&context);
```

这两句创建 Verilator 上下文和硬件模型。`context.commandArgs()` 是对象函数调用；`npc.pc` 访问对象成员；`npc.rootp->...` 通过内部指针访问寄存器堆。现有 `sim_step(npc)` 接口用 C++ 引用传参，所以调用时不写 `&`；本学习版自己写的辅助函数则统一用指针。

`goto finish` 只负责在失败时跳到统一的 `sim_close()`，确保关闭波形并调用模型的 final。也可以改成多处 return，但每处都必须先清理模型。

## 5. 和原版有什么差别

| 原版写法 | 学习版写法 |
|---|---|
| 类成员形式的检查函数 | `check_value(struct Check *, ...)` |
| `std::vector<Difference>` | 立即打印差异，在整步结束后停止 |
| `std::string` 拼接寄存器名 | `char name[32]` + `snprintf` |
| `auto`、范围 for | 显式类型、普通 for |
| 直接调用 EMU 类 | 小适配层提供普通函数 |
| 期望文件、完整 PC 轨迹容器 | 本版省略，保留逐指令比较和最终内存比较 |

计数方式也简化了，不再保持原版“每步恰好 17 项”的主计数。

本版正常结束只接受 ebreak；遇到非法指令，即使两边一致拒绝，也返回失败。不支持原版的预期非法测试模式。它也不解析手写 EXPECT，所以不能代替 E5 原版全部验收。

DiffTest PASS 表示两边一致，不要求 a0=0。E5 的数组求和程序 a0=10 仍应 PASS。E6 的“a0=0 表示程序成功”是 AM 的另一层约定。参考模型有共同错误时仍可能一致，因此原来的独立手写期望测试仍然有价值。

## 6. 运行

在 WSL 中：

```bash
cd /mnt/e/ysyx/e/e6/learning
make run
make wave
```

默认汇编 E5 的 `array_sum.s` 后运行。`make wave` 生成 `build/wave.fst`，可用 GTKWave 打开。

换一个程序：

```bash
python3 ../../e5/npc/tools/mkprog.py \
    ../../e5/npc/tests/programs/acceptance/byte_sum.s -o build/byte_sum.bin
make run PROGRAM=build/byte_sum.bin
```

这是明确放在 E 盘的学习副本，以上 `/mnt/e` 路径用于运行这个副本，不改变你正式的 WSL 工程位置。
