# F5支持数列求和的简单处理器

## 设计一个只有一条指令的sCPU

虽然这个CPU比较简单,但他依旧保留有一个CPU该有的基本功能:取指(fetch)、译码(decode)、执行(execute)、更新PC(PC->PC+1).

### 寄存器的位宽

- PC位宽为8位,初值为0
- GPR有4个,位宽均为8位
- 支持如下3条指令

```text
 7  6 | 5  4 | 3  2 | 1  0
------+------ +------+------
 0  0 |  rd  | rs1  | rs2      R[rd]=R[rs1]+R[rs2]    add指令,寄存器相加
------+------+-------+------
 1  0 |  rd  |    imm           R[rd]=imm              li指令,装入立即数,高位补0
------+------+--------------
 1  1 |    addr     | rs2       if (R[0]!=R[rs2]) PC=addr
                                  bner0指令,若不等于R[0]则跳转
```

## 取指(fetch)

首先需要设计一个PC寄存器,用于保存当前指令的地址.对于sISA来说,3条指令都不会访问数据存储器,只有取指操作需要从存储器中读出指令,因此这里可以采用ROM(Read-Only Memory,只读存储器).

数列求和程序一共有8条指令,每条指令长度为8bit,所以这里需要一个`8×8bit`的ROM.因为ROM深度为8,所以只需要3位地址就能选中其中一条指令.虽然PC本身是8位,但当前程序只使用PC的低3位`PC[2:0]`作为ROM的选择信号.

我使用一个数据位宽为8位、选择位为3位的8选1多路选择器模拟ROM,8个数据输入分别接8位常量:

| PC | 机器码 | 汇编指令 |
|---:|---:|---|
| 0 | `8A` | `li r0,10` |
| 1 | `90` | `li r1,0` |
| 2 | `A0` | `li r2,0` |
| 3 | `B1` | `li r3,1` |
| 4 | `17` | `add r1,r1,r3` |
| 5 | `29` | `add r2,r2,r1` |
| 6 | `D1` | `bner0 r1,4` |
| 7 | `DF` | `bner0 r3,7` |

取指方向:

```text
PC寄存器输出8位地址
        -> 分线器取PC[2:0]
        -> ROM多路选择器
        -> 输出8位instruction
        -> 进入decoder
```

这里的`instruction`只是给ROM输出线路起的名字,并不是一个新的元件.

## 译码(decode)

取出指令后,接下来要按照ISA格式把不同字段拆出来.我将ROM输出的8位`instruction`接入分线器:

```text
instruction[7:6] -> opcode
instruction[5:4] -> rd
instruction[3:2] -> rs1
instruction[1:0] -> rs2
instruction[3:0] -> imm
instruction[5:2] -> addr
```

同一组二进制位在不同指令中会有不同含义.例如`instruction[3:0]`在`li`中表示立即数,在`add`中又可以继续拆成`rs1`和`rs2`.这些线路可以同时存在,最后由控制信号决定哪一条数据通路真正起作用.

为了判断当前是哪一条指令,我将2位`opcode`接入一个2-4译码器:

```text
输出0 -> is_add   (opcode=00)
输出1 -> 暂时不用 (opcode=01)
输出2 -> is_li    (opcode=10)
输出3 -> is_bner  (opcode=11)
```

这些输出是CPU后面最主要的控制信号.

## 搭建4×8位GPR

GPR由4个8位寄存器组成,分别为R0、R1、R2、R3.四个寄存器共享写数据和时钟,但写使能需要分开.

```text
wdata -> R0.D、R1.D、R2.D、R3.D
CLK   -> R0.CLK、R1.CLK、R2.CLK、R3.CLK
RESET -> R0.R、R1.R、R2.R、R3.R
```

`rd`表示要写入哪个寄存器,因此我把`instruction[5:4]`接入另一个2-4译码器,得到`RD0~RD3`四根独热信号.

`li`和`add`都会写GPR,而`bner`不会写GPR,所以全局写使能为:

```text
RegWrite = is_li OR is_add
```

每个寄存器最终的写使能为:

```text
R0.WE = RegWrite AND RD0
R1.WE = RegWrite AND RD1
R2.WE = RegWrite AND RD2
R3.WE = RegWrite AND RD3
```

这样四个寄存器的D端虽然都能看到同一个`wdata`,但在一个时钟上升沿中只会有`rd`指定的寄存器被写入.

## 先实现li指令

`li`需要把指令中的4位`imm`写入8位GPR,所以需要使用位扩展器进行零扩展:

```text
instruction[3:0]
        -> 4位转8位零扩展器
        -> imm8
```

这里的`imm8`也是线路名称,表示立即数经过零扩展后的8位结果.

在只测试`li`时,可以先让`wdata=imm8`,然后依次执行PC为0到3的指令.每次都先让时钟保持为0,检查指令、立即数、rd、wdata和写使能,确认正确后再产生一次`0->1`的时钟上升沿.

执行完前4条指令后,GPR状态应该为:

```text
R0=0A
R1=00
R2=00
R3=01
```

## 添加add指令

`add`需要同时读出两个源寄存器,所以GPR需要两个读端口.每个读端口都使用一个数据位为8位、选择位为2位的4选1多路选择器.

两个读MUX的数据输入完全相同:

```text
输入0 <- R0.Q
输入1 <- R1.Q
输入2 <- R2.Q
输入3 <- R3.Q
```

不同的是选择信号:

```text
instruction[3:2] -> 读端口1选择端 -> rdata1
instruction[1:0] -> 读端口2选择端 -> rdata2
```

将`rdata1`和`rdata2`接入一个8位加法器,进位输入`Cin`接常量0:

```text
rdata1 -> 加法器输入A
rdata2 -> 加法器输入B
Cin=0
加法器输出 -> add_result
```

此时GPR可能写入立即数,也可能写入加法结果,所以需要增加一个8位二选一写回MUX:

```text
输入0 <- imm8
输入1 <- add_result
选择端 <- is_add
输出   -> wdata
```

因此:

```text
li时:is_add=0,wdata=imm8
add时:is_add=1,wdata=add_result
```

执行地址4的`add r1,r1,r3`后,R1应该从`00`变为`01`;继续执行地址5的`add r2,r2,r1`后,R2应该从`00`变为`01`.

## 更新PC(PC->PC+1)

PC也是一个8位寄存器.PC的Q端一方面送到ROM进行取指,另一方面送入一个8位加法器计算`PC+1`.

```text
PC.Q -> ROM地址分线器
PC.Q -> PC加法器输入A
8位常量01 -> PC加法器输入B
Cin=0
PC加法器输出 -> PC.D
```

PC的写使能恒为1,并且与4个GPR共用同一个时钟和RESET.这样在一个时钟上升沿到来时,GPR完成当前指令要求的写入,PC也同时更新为下一条指令地址.

复位后连续执行,应该观察到:

```text
PC:00 -> 01 -> 02 -> 03 -> 04 -> 05 -> 06
```

对应的指令也会依次变为:

```text
8A -> 90 -> A0 -> B1 -> 17 -> 29 -> D1
```

## 添加bner指令

`bner`需要比较`R0`和`R[rs2]`.读端口2本来就是由`rs2`选择,可以直接复用.读端口1原本由`rs1`选择,因此要在它的选择端前增加一个2位二选一MUX:

```text
输入0 <- rs1
输入1 <- 2位常量00
选择端 <- is_bner
输出   -> raddr1 -> 读端口1大MUX选择端
```

这样执行`add`时端口1读取`R[rs1]`,执行`bner`时端口1固定读取`R0`.

之后将`rdata1`和`rdata2`同时接入一个8位比较器.这里我只关心两者是否相等:

```text
rdata1 -> 比较器输入A
rdata2 -> 比较器输入B
比较器A=B输出 -> 非门 -> not_equal
```

只有当前指令为`bner`,并且两个寄存器不相等时才真正跳转:

```text
branch_taken = is_bner AND not_equal
```

跳转地址为`instruction[5:2]`,它只有4位,需要先零扩展为8位:

```text
instruction[5:2] -> 4位转8位零扩展器 -> branch_addr
```

最后在PC寄存器D端前增加一个8位二选一MUX:

```text
输入0 <- PC+1
输入1 <- branch_addr
选择端 <- branch_taken
输出   -> PC.D
```

因此PC更新逻辑为:

```text
branch_taken=0:PC<-PC+1
branch_taken=1:PC<-branch_addr
```

## 完整运行数列求和程序

复位后,CPU先执行4条`li`完成初始化,然后在地址4、5、6之间循环:

```text
4:add r1,r1,r3    让R1每轮加1
5:add r2,r2,r1    把当前R1累加到R2
6:bner0 r1,4      如果R1还不等于10就跳回4
```

所以PC会经历多次:

```text
4 -> 5 -> 6 -> 4 -> 5 -> 6 -> ...
```

这不是PC更新错误,而是程序正在进行求和循环.当R1最终等于`0A`时,地址6的跳转条件不成立,PC顺序更新到7.地址7的指令会一直跳回7,使处理器停留在最终状态.

最后观察到:

```text
PC=07
R0=0A
R1=0A
R2=37
R3=01
```

其中`R2=0x37=55`,说明处理器成功算出了`1+2+...+10`的结果.

## BUG调试记录

### 1. 用MUX模拟ROM时发生错误连接

ROM 使用一个 8 位宽、8 选 1 的多路选择器实现：

```text
选择位：3
数据位：8
```

最开始曾把多条指令常量线路连接到一起，还把 PC 地址线接到了 MUX 的数据输出端。正确连接应为：

```text
8个指令常量 → MUX的8个数据输入
PC[2:0]      → MUX的选择端
MUX输出       → instruction[7:0]
```

调试心得：MUX 的数据输入、选择端和输出端必须分清。遇到位宽错误时，应先检查端口类型，而不是反复修改常量值。

### 2. `rdata` 显示 `UUUUUUUU`

现象：GPR 读端口输出一直是未定义值 `U`。

原因有两部分：

1. 寄存器尚未复位，内部状态本身是未定义的。
2. 读端口 MUX 最初没有接入 `R0.Q～R3.Q`。

正确连接：

```text
R0.Q → 读MUX输入0
R1.Q → 读MUX输入1
R2.Q → 读MUX输入2
R3.Q → 读MUX输入3
rs    → 读MUX选择端
```

解决方法是先复位全部寄存器，再确认 MUX 的数据输入连接的是寄存器 `Q`，而不是 `D`、`EN` 或指令字段。

调试心得：看到 `U` 时应该从信号源开始检查。先看每个寄存器的 `Q` 是否确定，再看选择信号，最后看 MUX 输出。

### 3. `add` 执行后R1错误地变成`07`

这是本次最典型的故障。

在地址 `4`：

```text
instruction = 17
指令语义     = add r1,r1,r3
imm8         = 07
add_result   = 01
```

虽然 `add` 不使用立即数，但立即数零扩展电路仍然会把指令低 4 位解释成 `07`。这属于组合电路正常产生的无关数据。

真正的问题是写回 MUX 选错了输入，导致 `wdata=07`，并在时钟上升沿写入 R1。

写回 MUX 的正确连接：

```text
输入0 ← imm8
输入1 ← add_result
选择端 ← is_add
输出   → wdata → R0.D～R3.D
```

因此：

```text
li：  is_add=0，选择imm8
add： is_add=1，选择add_result
```

调试时我把加法器原始输出和 MUX 输出分开观察：

```text
ADD_RESULT_RAW：直接观察加法器输出
WDATA：观察写回MUX输出
```

这样就能快速判断错误位于加法器之前，还是写回选择阶段。

### 4. 修好线路后，R1仍然显示`07`

原因不是线路仍然错误，而是 `07` 已经被寄存器保存。组合逻辑修改不会自动改变寄存器中的旧状态。

必须先区分：

```text
R1.D：当前准备写入的数据
R1.Q：当前已经保存的数据
```

修好线路后，应确认：

```text
R1.D  = 01
R1.WE = 1
RESET = 0
```

然后通过新的时钟上升沿写入，或者复位后重新执行完整指令序列。

调试心得：修改时序电路后必须复位并重新运行。不能用旧状态判断新线路是否正确。

### 5. `rdata1=07`并不是新的MUX故障

当 R1 已经被错误写成 `07` 时，地址 `4` 的 `rs1=01` 会正确选择 R1，因此：

```text
R1.Q   = 07
rdata1 = 07
```

这反而说明读 MUX 正确地读出了 R1。错误源仍然是此前的写回，而不是当前的读取。

调试心得：不要看到错误值就立即怀疑当前元件。先沿数据流向上追踪，确认它是在什么时钟沿首次出现的。
